# Runbook：服务端发布

## 适用场景

- 服务端部署、版本发布、滚动更新、配置与 Secret 变更，或回滚。

## 前置读取

- [服务端运行](../engineering/server/runtime.md)
- [可观测性](../problems/observability.md)

## 环境与配置

### 环境

- 至少区分开发、测试（或预发）与生产；每个环境使用独立的数据库、缓存、队列与 Secret，不共用生产实例。
- 开发与生产环境只用于运行、观察、验证和回查；修复走发布流程，不在远端改代码或手工改 schema。

### 配置

- 配置全部来自环境变量或配置中心，代码与镜像中不写环境地址、账号与凭证。
- 必需配置在启动时校验：缺失或格式错误即退出并打印变量名，不用兜底默认值继续运行。
- 本地默认值只用于本地开发，不进入镜像与发布产物。

### Secret

- Secret 由平台注入，不写入仓库、镜像、日志与构建产物；不同环境使用独立取值。
- 轮换分四步：新增取值 → 新旧同时接受 → 切换使用 → 移除旧值；结束前确认全部实例已使用新值。
- 获取 Secret 失败时启动即失败，不带着空凭证运行。

## 部署规则

### 无状态与水平扩展

- 服务端必须无状态：会话、上传临时文件、定时任务、本地缓存外置到共享存储、缓存或队列，请求可由任意实例处理。
- 新增有状态逻辑前先说明扩展方案；本机文件与内存计数只能作为可丢失的优化。

### 滚动更新

- 新旧实例并行期间必须同时可用：接口与数据库变更保持向后兼容，破坏性变更拆成两步发布（先兼容读，再切换写）。
- 数据库迁移先于新版本实例启动，且迁移本身要兼容旧实例仍在运行的状态。
- 回滚只回退代码，不回退已执行的数据迁移；不可逆迁移在发布前备份并写入发布记录。

### 健康检查

- `/healthz` 只反映进程存活，`/readyz` 反映依赖就绪；新实例通过 `/readyz` 后才接流量。
- 旧实例收到 SIGTERM 后停止接收新请求，在优雅停机窗口内处理完在途请求再退出；窗口长度大于最长请求耗时。

### 发布观察

- 每次发布记录版本号、提交、变更内容、迁移项与回滚方式。
- 发布后按[可观测性](../problems/observability.md)的看板观察错误率、延迟与依赖状态，达到基线后才结束发布。

## 步骤

1. 确认目标环境、版本号与产物正确，必需配置与 Secret 已就绪。
2. 按[项目阶段](../../AGENTS.md#项目阶段)执行数据库迁移，确认迁移可被仍在运行的旧实例兼容。
3. 构建并推送产物：`<构建命令>`。
4. 滚动发布，新实例通过 `/readyz` 后接入流量，确认旧实例优雅退出。
5. 观察错误率、延迟与依赖指标，异常时回滚代码版本。
6. 记录发布结果与遗留问题。

## 验证

- `/healthz` 与 `/readyz` 通过，新实例全部就绪。
- 旧实例在优雅停机窗口内退出，发布期间无请求失败。
- 关键指标与错误率处于基线。
- 配置与 Secret 无硬编码，缺失时启动失败。
- 迁移在旧实例运行期间不产生错误，回滚路径已确认可执行。
