# Runbook：客户端发布

## 适用场景

- 客户端版本发布、灰度扩量、强制更新配置，或回滚客户端版本。

## 前置读取

- [客户端运行](../engineering/client/runtime.md)

## 发布方式

### 各端差异

| 端 | 分发方式 | 生效时机 | 回滚方式 |
| --- | --- | --- | --- |
| App | 应用商店 | 审核通过后由用户升级 | 已安装版本无法回退，只能停止灰度并发布新版本 |
| Web | 静态资源直接发布 | 发布即生效 | 回退资源或关闭入口 |
| 桌面 | 自动更新 | 启动时或定时更新 | 回退版本清单，暂停推送 |

- 按项目实际端删减上表；各端的构建参数与产物位置见[客户端运行](../engineering/client/runtime.md)。
- 移动端与桌面端不能假设用户会立刻升级：发布前先确定最低支持版本，并确认服务端已兼容该版本。
- Web 发布的静态资源带内容指纹，入口 HTML 不缓存，避免用户命中新旧混合资源。

### 版本号与产物

- 每次发布递增版本号，产物由统一构建入口生成，不手工打包；同一版本号不重复发布。
- 每个产物可追溯到提交与构建参数，构建参数中不写死环境地址。
- 发布记录写明版本号、提交、变更内容、最低支持版本与回滚方式。

### 灰度

- 默认按 5% → 25% → 50% → 100% 分阶段扩量，每阶段至少观察一个完整业务周期（建议 24 小时）。
- 灰度期间监控崩溃率、启动成功率、关键流程成功率与接口错误率；任一项高于基线即停止扩量。
- 未达标的版本停止发布并回滚，不在灰度中叠加修复版本。

### 强制更新

- 只在旧版本无法安全提供服务时启用：契约破坏、安全问题、数据不兼容。
- 启用前确认最低支持版本、提示文案、跳转地址在各端可用；被拦截的用户能看到原因与出口。
- 能通过服务端兼容解决的不强制更新。

## 版本兼容

- 服务端契约变更必须明确客户端最低支持版本；窗口内旧客户端的请求要么正常处理，要么返回可识别的「请升级」错误码。
- 客户端对未知字段、未知枚举值与新增错误码必须能忽略或降级，不因服务端新增内容崩溃。
- 兼容要求按[项目阶段](../../AGENTS.md#项目阶段)执行：开发阶段不保留旧客户端兼容逻辑，上线后才维护兼容窗口。

## 步骤

1. 确定版本号、最低支持版本与契约变更，确认服务端已兼容或已先发布。
2. 通过统一入口构建各端产物，记录提交与构建参数。
3. 按端发布：Web 直接发布，App 提交审核，桌面端先发布版本清单。
4. 按灰度阶段扩量，逐阶段核对崩溃率、关键流程与接口错误。
5. 达标后全量；异常时停止扩量并按该端方式回滚。
6. 记录版本、灰度结论与遗留问题。

## 验证

- 旧版本客户端在兼容窗口内可正常使用，或被明确引导升级。
- 灰度各阶段指标达到发布标准后才扩量。
- 产物可追溯到提交与构建参数，版本号唯一。
- 回滚路径已在发布前确认可执行。
