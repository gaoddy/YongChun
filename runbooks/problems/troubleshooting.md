# Runbook：问题排查

## 适用场景

- 测试失败、线上异常、性能退化，或行为与预期不符。

## 前置读取

- [服务端分层](../engineering/server/layering.md)
- [客户端分层](../engineering/client/layering.md)

## 原则

- 先定位根因，不修症状；证据收集完成前不提出修复。
- 一次只验证一个假设，用最小改动验证假设成立与否。

## 排查维度

| 维度 | 检查内容 |
| --- | --- |
| 数据链路 | 请求入口 → 各层 → 存储与外部服务，逐段确认输入输出与失败边界 |
| 软件架构 | 分层职责、依赖方向、装配与生命周期是否符合约定 |
| 数据结构 | 字段类型、约束、索引、序列化、schema 演进 |
| 运行环境 | 环境变量、配置、版本、网络与资源限制 |
| 变更与版本 | 最近的代码、依赖、配置、迁移与发布变更 |
| 代码逻辑 | 边界条件、空值、异常分支、状态机、幂等 |
| 输入与数据质量 | 参数、脏数据、编码、时区、数值精度 |
| 依赖与外部服务 | 数据库、缓存、队列、第三方 API、超时、重试、限流 |
| 并发与时序 | 竞态、锁、事务隔离、时钟偏差、重试重复、缓存一致性 |
| 契约与版本匹配 | 接口契约、客户端与服务端版本、生成物是否同步 |
| 权限与安全 | 认证、授权、租户隔离、越权 |
| 复现与影响范围 | 稳定复现步骤、触发条件、数据规模、受影响对象 |

## 步骤

1. 完整阅读错误信息与堆栈，记录时间、请求 ID 与错误码。
2. 稳定复现；无法复现时先加诊断埋点，收集各组件边界的输入输出。
3. 对照「变更与版本」，列出异常时间窗口内的变更。
4. 按排查维度建立单一假设，逐项排除并记录证据。
5. 输出根因结论：根因所在层、影响范围与稳定复现条件；未确认根因时不进入修复。

## 验证

- 根因结论有证据支持，假设可被反例推翻。
- 复现条件可稳定触发，影响范围已界定。
- 修复方案不属于本 runbook 范围，确认根因后按[修复决策](../problems/fix-decision.md)执行。
