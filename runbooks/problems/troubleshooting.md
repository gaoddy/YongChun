# Runbook：问题排查

## 适用场景

- 测试失败、线上异常、性能退化，或行为与预期不符。

## 前置读取

- [服务端分层](../engineering/server/layering.md)
- [客户端分层](../engineering/client/layering.md)

## 原则

- 先定位根因，不修症状；证据收集完成前不提出修复。
- 用第一性原理追根因：连续追问「为什么」，直到数据、控制流或依赖关系能解释现象；不以框架行为、既有惯例或「本来就这样」作为解释终点。
- 用户给出的原因判断只作为待验证假设；先确认要解释的现象与问题定义，再开始排查。
- 一次只验证一个假设，用最小改动验证假设成立与否。

## 反馈回路

- 排查的第一个动作是建立能重复触发故障的反馈回路，不是读代码找原因；没有回路时不进入假设阶段。
- 反馈回路是可由 agent 自动执行、快速返回通过或失败的最小信号；按成本从低到高选择：失败测试、`curl` 或 HTTP 脚本、带固定输入的 CLI、无头浏览器脚本、回放已捕获的请求或事件日志、最小独立复现脚本、随机输入循环、二分定位脚本、新旧版本对照。
- 回路质量按三件事改造：更快（只初始化必要依赖）、信号更尖锐（断言具体症状，而不是「没崩」）、更确定（固定时间与随机种子，隔离文件系统与网络）。
- 现有回路执行超过约 30 秒或结果不稳定时，先改造回路再排查，不以慢回路代替证据。
- 波动型缺陷不追求一次稳定复现，而以提高复现率为目标：重复触发、并行加压、收窄时序窗口；复现率过低时继续提高，不按「偶发」放过。
- 无法建立回路时停止排查，向用户说明已尝试的方式，并索取以下之一：可复现的环境、捕获物（抓包、日志、崩溃转储、带时间戳的录屏）、临时观测埋点授权；不得在无回路时进入假设验证。

## 假设

- 一次列出 3–5 个按可能性排序的假设，再逐个验证；只提一个假设会锚定在第一个看起来合理的想法上。
- 每个假设必须写出预测：若 X 是原因，则改动 Y 后故障消失、改动 Z 后加重；写不出预测的假设丢弃或改写。
- 验证前列出排序给用户确认，用户掌握的近期变更信息常能立即调整次序；用户不在线时按自己的排序继续，不空等。
- 一次只改一个变量；每个探测手段对应一个具体预测，不用「全量打日志再 grep」。
- 排查期新增的日志带唯一前缀（如 `[DEBUG-a4f2]`），收尾用一次 grep 清除；无前缀的调试日志不留在代码中。

## 排查维度

| 维度 | 检查内容 |
| --- | --- |
| 数据链路 | 请求入口 → 各层 → 存储与外部服务，逐段确认输入输出与失败边界 |
| 软件架构 | 分层职责、依赖方向、装配与生命周期是否符合约定 |
| 数据结构 | 字段类型、约束、索引、序列化、schema 演进 |
| 运行环境 | 环境变量、配置、版本、网络与资源限制 |
| 变更与版本 | 最近的代码、依赖、配置、迁移与发布变更 |
| 代码逻辑 | 边界条件、空值、异常分支、状态机、幂等 |
| 输入与数据质量 | 参数、脏数据、编码、时区、数值精度 |
| 依赖与外部服务 | 数据库、缓存、队列、第三方 API、超时、重试、限流 |
| 并发与时序 | 竞态、锁、事务隔离、时钟偏差、重试重复、缓存一致性 |
| 契约与版本匹配 | 接口契约、客户端与服务端版本、生成物是否同步 |
| 权限与安全 | 认证、授权、租户隔离、越权 |
| 复现与影响范围 | 稳定复现步骤、触发条件、数据规模、受影响对象 |

## 步骤

1. 确认要解释的现象与问题定义：区分用户描述的症状、原因判断与期望结果；问题定义不成立时先回到产品或需求确认。
2. 完整阅读错误信息与堆栈，记录时间、请求 ID 与错误码。
3. 建立反馈回路并跑通：确认回路复现的是用户描述的那个故障，而不是附近另一个失败；无法复现时按「反馈回路」一节处理，未建立回路时不进入下一步。
4. 对照「变更与版本」，列出异常时间窗口内的变更。
5. 列出 3–5 个可证伪假设并排序，逐个验证并记录证据；一次只改一个变量。
6. 输出根因结论：根因所在层、影响范围与稳定复现条件；未确认根因时不进入修复。
7. 清除带前缀的调试日志与临时复现脚本，确认原场景不再复现。

## 验证

- 根因结论有证据支持，假设可被反例推翻。
- 根因已追到机制层，未把框架行为、既有惯例或用户给出的原因判断直接当作根因。
- 复现条件可稳定触发，影响范围已界定；波动型缺陷给出了可重复达到的复现率。
- 排查开始前已有可自动执行、快速返回结果的反馈回路；无法建立回路时已停止排查并索取环境或捕获物，未在无回路时提出假设。
- 假设验证一次只改一个变量，结论对应具体预测。
- 带前缀的调试日志与临时复现脚本已清除，代码中无残留。
- 修复方案不属于本 runbook 范围，确认根因后按[修复决策](../problems/fix-decision.md)执行。
