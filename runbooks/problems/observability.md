# Runbook：可观测性

## 适用场景

- 新增或调整日志、指标、追踪与告警；服务上线前补齐观测能力；排查时发现信号不足，需要补埋点。

## 原则

- 信号要能回答三个问题：出了什么问题、影响谁、从什么时候开始。答不上的信号不加。
- 只采集和告警可行动的信号：没有对应处理动作的指标不采集，没有处理步骤的告警不配置。
- 观测代码与业务代码在同一任务内交付，不等到出问题再补。

## 日志

### 格式与字段

- 结构化输出（JSON 或键值对），一行一条，禁止多行拼接与自由文本。
- 固定字段：时间（UTC、ISO 8601）、级别、请求 ID、模块、消息、错误码；有用户或租户上下文时一并带上。
- 消息写发生了什么，变量放字段里，不要拼进消息文本。
- 错误日志必须能定位：错误码、堆栈、关键入参（脱敏后）、失败对象标识；不写 `failed`、`error occurred` 这类无法行动的文本。

### 级别

| 级别 | 使用场景 |
| --- | --- |
| error | 请求失败、数据不一致、需要人介入的异常 |
| warn | 可恢复异常、降级、重试后成功、接近限额 |
| info | 请求入口与出口、状态变更、启动与配置加载 |
| debug | 仅本地或临时排查时开启，生产默认关闭 |

- 同一异常只在一个层级记录一次，不在每层重复打印。
- 生产关闭 debug；需要时用动态开关临时开启，并约定关闭时间。

### 请求 ID

- 入口生成或透传 `X-Request-Id`：客户端发起请求时生成并记录，服务端沿用，响应头回传。
- 跨服务调用、队列消息、异步任务传递同一个 ID；异步任务落库时一并保存，便于事后回查。
- 日志、错误响应与追踪共用该 ID，排查时以它串起全链路。

### 敏感信息

- 不记录密码、令牌、完整证件号、手机号、银行卡号与请求体原文；确需记录时脱敏保留末位。
- 采集与保留：{{日志级别、保留天数、存储位置、访问权限}}。

### 禁止做法

- 用日志做业务统计，改用指标。
- 在循环内逐条打印明细。
- 打印整个对象或完整请求体。

## 指标

### 必备指标

- 请求量、错误率、延迟 P50/P95/P99，按路由与状态码分组。
- 依赖调用：数据库、缓存、队列、外部 API 的调用量、失败率、超时与耗时。
- 资源与容量：实例数、CPU、内存、连接池占用、队列积压。
- 至少一个业务指标（如核心链路的成功数），用于判断功能是否可用，而不只是进程是否存活。

### 采集规则

- 指标名与标签保持稳定；请求 ID、用户 ID、时间戳等高基数数据不做标签。
- 失败按原因拆分（超时、4xx、5xx、依赖错误），不能只统计总数。
- 指标通过统一封装记录，不在业务代码里散落手写。

### 看板

- 一块看板对应一条核心链路，首屏放请求量、错误率、延迟与依赖状态。
- 看板配置存入仓库（`<看板配置目录>`）或可导出，避免只在平台上手工搭建。
- 发布时以看板判断是否回滚，判断标准见[服务端发布](../delivery/server-deploy.md)。

## 追踪

- 是否引入链路追踪、使用的系统与采样率：{{是否引入、系统、采样率}}。
- 引入时：入口创建 span，跨服务通过请求头传播上下文；span 名用「服务.操作」，标注路由、状态码与依赖名。
- 采样默认低比例，错误请求与慢请求全量保留；本地与测试环境可全量。

## 告警

- 每条告警绑定一个处理动作（对应 runbook 或回滚步骤），无法行动的告警直接删除。
- 阈值基于基线：先观察一到两周实际分布，取明显偏离的区间，不用拍脑袋的固定值。
- 分级：page（核心链路不可用，立即处理）、ticket（当日处理）、info（仅记录）。
- 同一根因的多条告警合并；依赖故障引发的下游告警做抑制，只保留下游中可直接处理的那条。
- 告警规则与发布走同一流程，变更后确认触发与恢复都符合预期。

## 步骤

1. 列出核心链路与已知失败模式（超时、依赖不可用、数据不一致、容量不足），确定每类需要的信号。
2. 按日志规则接入结构化日志与请求 ID，确认一条请求可被完整串起。
3. 接入必备指标并建立看板，标注当前基线。
4. 依据实际分布配置告警，为每条告警写明处理动作。
5. 发布后在真实流量下验证：从一个错误响应能定位到具体请求、服务与失败点。
6. 线上问题复盘后，补齐当时缺失的信号。

## 验证

- 任一请求可用请求 ID 在日志中串起完整调用链。
- 看板能回答「是否异常、从何时开始、影响哪些路由」。
- 每条告警都有处理动作，最近一次触发能按文档处理。
- 日志不含敏感信息，生产环境 debug 已关闭。
- 定位一个线上错误不需要改代码加日志。
