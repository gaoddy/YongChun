# Runbook：补充测试与验证

## 适用场景

- 新增功能、修复缺陷或调整接口后补充测试与执行验证。

## 前置读取

- [Make 构建入口](make.md)

## 测试范围

- 只测试本次改动涉及的功能：改动直接对应的入口、分支与依赖链，以及受其直接影响的调用方。
- 不执行全量测试，不回归与本次改动无关的功能；仓库既有测试全量通过不构成本任务的验收条件。
- 改动跨模块时按实际调用链扩大范围，不按目录、文件数量或「顺手一并测」扩大。
- 影响面不明确时，先检索该功能的调用方与引用确定范围；仍无法确定时只跑该功能的端到端路径，并在交付说明中写明未覆盖的部分。
- 例外：合并队列交付按[Worktree 合并队列交付](../delivery/worktree-delivery.md)执行定向与全量验证。

## 测试同步

- 功能改动时同步更新对应测试：行为改了，覆盖该行为的测试在同一交付内一起改，不留仍按旧行为断言的用例。
- 新增入口、分支、参数或错误码时补上对应测试；删除、合并或重命名功能时同步删除、合并或改名其测试。
- 测试未随功能更新时任务不算完成；不得用注释、跳过或放宽断言让旧测试通过。
- 只同步本次改动涉及的测试，不连带改写在范围内无关的测试。

## 缺陷测试

- 先写能稳定复现缺陷的用例，确认修复前失败、修复后通过。
- 服务端：失败用例并入 `<e2e 入口>` 随交付提交，成为长期回归。
- 客户端：失败用例按[客户端测试策略](#客户端测试策略)处理：覆盖缺陷复现路径的保留为长期回归，其余验证后删除。
- 缺陷由既有测试漏检导致时，同一交付内补上该路径的覆盖，不留同一路径再次漏检。

## 服务端测试策略

- 不维护单元测试文件，只保留端到端测试及其 `<e2e 入口>`；临时验证产生的其他测试文件、fixture、testdata 及测试专用支持文件不得随交付提交。
- 例外：并发、分片与关键状态机的长期回归测试保留，随交付提交；不新增其他单元测试。
- e2e 使用真实依赖（`<数据库>`、连接池、`<缓存>`）；核心链路的 SKIP 不算通过。
- e2e 缺少依赖时先启动环境，不允许改为 mock。

## 客户端测试策略

- 区分长期回归测试与临时验证测试：长期回归随交付提交并纳入长期测试集，临时验证在任务分支内编写、验证完成后删除。
- 长期保留的判定：用户关键路径、已发生过的缺陷复现路径、易回归的状态与交互；一次性数据核验与调试断言不保留。
- 长期回归测试及其 fixture、golden、integration / driver 随交付提交，落点按项目约定且不放在源码目录内，见[目录结构](../engineering/directory-structure.md)。
- 删除临时测试及其专用支持文件后执行 `<静态检查命令>`，并至少回查一次真实接口或关键页面数据。
- 实机验证优先使用稳定设备与非 debug 构建。

## 测试数据

- 用例自带数据准备与清理，不依赖其他用例或手工预置的数据，同一测试可重复执行。
- 用例之间不依赖执行顺序；需要特定前置数据时在用例内显式建立。
- 用例写入的数据在结束时清理；无法清理时使用可整体重建的独立数据范围。
- 依赖不可用时先启动环境，不以 mock 或旧快照代替真实数据。

## 断言与失败定位

- 断言同时输出期望值与实际值，失败信息能直接定位到功能路径与数据。
- 区分环境故障与功能失败：依赖未就绪、连接失败的报错一眼可辨，不与断言失败混在一起。
- 等待状态变化使用显式等待或轮询到条件成立，不用固定 sleep 代替。

## 并发与性能验证

- 改动涉及锁、连接池、队列、批量接口、限流或幂等重复提交时，补并发或多请求用例，验证竞态、重复写入与资源上限。
- 并发用例重复执行多轮，结果稳定才算通过；偶发失败按缺陷处理，不重跑掩盖。
- 性能基准与压测不在本 runbook 范围，性能退化按[问题排查](../problems/troubleshooting.md)定位。

## 步骤

1. 按本次改动涉及的功能选择测试层级，优先真实依赖的端到端测试；范围外的用例不执行。
2. 明确成功、失败与边界用例，覆盖权限与异常路径；涉及并发或资源竞争的改动补并发用例。
3. 同步更新本次改动涉及的现有测试，使其与新行为一致。
4. 执行验证矩阵，记录命令输出与退出状态。
5. 修复失败项，不通过跳过、注释或放宽断言处理。
6. 交付前清理临时测试与 fixture，保留需要长期回归的测试。

## 验证

- 验证矩阵全部通过，核心链路的 SKIP 不算通过。
- 执行的测试只覆盖本次改动涉及的功能，没有执行全量测试或无关功能的回归。
- 本次改动涉及的测试已随功能更新，不存在仍按旧行为断言的用例。
- 缺陷失败用例已按端归位：服务端随 `<e2e 入口>` 提交，客户端覆盖复现路径的保留为长期回归。
- 客户端长期回归测试及其支持文件随交付提交，临时测试已删除。
- 用例自带数据准备与清理，不依赖执行顺序，可重复执行。
- 断言失败信息含期望与实际，能定位到功能路径；并发相关改动有对应并发用例。
- 关键链路有对应测试。
- 文档中的测试命令与仓库一致。
