# Runbook：Worktree 创建时机

## 适用场景

- 任务开始前判断是否需要创建 worktree，或不确定任务是否会产生文件修改。
- 创建、分支与清理的操作见[Worktree 与分支](worktree.md)；本文只规定何时创建。

## 规则

- 不修改仓库文件的任务不创建 worktree：只读观察、验证、回查、评审、答疑、检索、解释代码与查询状态直接在当前目录执行。
- 所有写入仓库文件的修改都创建 worktree，包括只改文档、规则或配置；改动量不作为豁免依据。
- 当前目录已经是本任务的 worktree 时直接在其中执行，不重复创建；其他目录下的修改一律先创建 worktree。
- 小改动只决定是否进入 plan 模式，不决定是否创建 worktree：改动合计约 10 行以内、不新增或删除文件，且不改变对外接口、数据模型、依赖或目录结构时，不进入 plan 模式。
- 超出小改动范围的修改在创建 worktree 后进入 plan 模式先定方案；只改文档或只改配置本身不构成豁免。
- 判定需要创建时只通过 `skills/worktree/worktree-guard/scripts/worktree_create.sh` 创建，不直接执行 `git worktree add`，见[Worktree 与分支](worktree.md)。
- 不确定是否会产生文件修改时，先以只读方式执行；确认需要修改后创建 worktree。
- 一个任务只创建一个 worktree；子 agent 不单独创建，执行位置见[Worktree 与分支](worktree.md)。
- 无法创建 worktree（没有可用基线分支、工作区不干净、基线不存在或目标已存在等）时任务阻塞：在任务报告中写明原因与需要的处理，不在当前目录或其他 worktree 修改，先修复基线或工作区后重新创建。
- 多任务并行时，每个会产生文件修改的任务分别创建 worktree；只读任务不因并行而创建。

## 判定

| 任务情况 | 是否创建 | 执行位置 | 是否用 plan 模式 |
| --- | --- | --- | --- |
| 只读观察、验证、回查、评审、答疑、检索、解释代码、查询状态 | 否 | 当前目录 | 否 |
| 修改代码、文档或配置，属于小改动 | 是 | 该任务的 worktree | 否 |
| 修改代码、文档或配置，超出小改动范围 | 是 | 该任务的 worktree | 是 |
| 是否产生文件修改不确定 | 先不建 | 当前目录只读执行，确认后按修改行创建 | 确认后按改动规模 |
| 无法创建 worktree | 不允许修改 | 任务阻塞，报告中写明原因 | — |

## 步骤

1. 判断任务是否需要写入仓库文件：只读任务直接在当前目录执行，不创建 worktree，也不进入 plan 模式。
2. 需要修改时按[Worktree 与分支](worktree.md)从基线分支创建 worktree 与分支；创建失败时阻塞并报告，不退回当前目录修改。
3. 判断是否属于小改动，只用于决定是否进入 plan 模式：属于则直接实施；超出范围则在实施前进入 plan 模式确定方案。
4. 在 worktree 内完成修改、验证、提交与合并。

## 验证

- 所有修改都发生在该任务的 worktree 内，没有在当前目录或其他 worktree 修改。
- 只读任务没有创建 worktree，也没有进入 plan 模式。
- 小改动创建了 worktree，但未创建计划目录。
- 超出小改动范围的修改在 worktree 内完成，并在实施前经过 plan 模式确认方案。
- worktree 由 `worktree_create.sh` 创建，未出现直接调用的 `git worktree add`。
- 无法创建 worktree 时任务已阻塞，报告写明原因与处理，未发生修改。
