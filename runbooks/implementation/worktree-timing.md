# Runbook：Worktree 创建时机

## 适用场景

- 任务开始前判断是否需要创建 worktree，或不确定任务是否会产生文件修改。
- 创建、分支与清理的操作见[Worktree 与分支](worktree.md)；本文只规定何时创建。

## 规则

- 不修改仓库文件的任务不创建 worktree：只读观察、验证、回查、评审、答疑、检索、解释代码与查询状态直接在当前目录执行。
- 只有需要修改代码、文档或配置时才创建 worktree。
- 改动量小、只改文档或只改配置不构成豁免；判定只看是否修改仓库文件，不看改动行数。
- 不确定是否会产生文件修改时，先以只读方式执行；确认需要修改后再创建。
- 一个任务只创建一个 worktree；子 agent 不单独创建，执行位置见[Worktree 与分支](worktree.md)。
- 仓库没有可用基线分支（如尚无首次提交）时无法创建 worktree；在任务报告中说明原因后直接在当前目录执行。
- 多任务并行时，只对各自会产生文件修改的任务分别创建 worktree；只读任务不因并行而创建。

## 判定

| 任务情况 | 是否创建 | 执行位置 |
| --- | --- | --- |
| 只读观察、验证、回查、评审、答疑、检索、解释代码、查询状态 | 否 | 当前目录 |
| 修改代码、文档或配置 | 是 | 从基线分支创建的 worktree |
| 修改代码、文档或配置，但改动量小 | 是 | 从基线分支创建的 worktree；不因改动小或只改文档豁免 |
| 是否产生文件修改不确定 | 先不建 | 当前目录只读执行，确认后再按上一行创建 |
| 没有可用基线分支（如尚无首次提交） | 无法创建 | 当前目录，并在报告中说明原因 |

## 步骤

1. 判断任务是否需要写入仓库文件：只读任务直接在当前目录执行，不创建 worktree。
2. 无法判断时，先以只读方式核对，确认会产生文件修改。
3. 确认需要修改后，按[Worktree 与分支](worktree.md)从基线分支创建 worktree 与分支。
4. 无法创建 worktree 时，在当前目录执行，并在报告中写明原因与执行目录。

## 验证

- 只读任务没有创建 worktree，也没有切换到其他目录。
- 修改任务在 worktree 内完成，分支基线正确。
- 未判定就开工的情况为零：不确定的任务先只读，后创建。
- 无法创建 worktree 时，报告写明原因与执行目录。
