# Runbook：讨论记录

## 适用场景

- 草案、方案探讨、技术咨询、需求澄清等尚未形成确定结论的交流。
- 已有承载文档（`docs/current/product/`、`docs/current/technical/`、版本基线或 runbook）时直接更新原文档，不建讨论记录。
- 目录位置与索引规则见[文档结构](../docs/structure/docs-structure.md)；结论回写见[文档回写](../docs/docs-sync.md)。

## 前置读取

- [文档写作](../docs/docs-writing.md)
- [文档结构](../docs/structure/docs-structure.md)

## 规则

- 讨论开始前建立 `docs/drafts/<主题>.md`；一个主题一个文件，文件名用小写 kebab-case。
- 每轮回复前先读该文件，以其中的已确认结论为起点；不从对话历史重新推断。
- 形成结论立即写入文件，不只留在消息里；每条结论标注「已确认」「待确认」或「已否决」。
- 新结论与文件不一致时先更新文件，再继续讨论，不并存两种说法。
- 文件只写结论、依据与待确认项，不写完整对话、无关背景与过程复述。
- 讨论记录不替代任务计划：任务拆分与进度按[任务计划](../version/plan.md)管理；不替代产品与技术方案文档。
- 结论稳定后回写承载文档，未决项写入版本 `open-questions.md`，随后删除讨论记录。
- 讨论不再继续时同样删除；讨论记录可随分支提交，但收尾删除，不随分支合入主分支。

## 文件结构

| 章节 | 内容 |
| --- | --- |
| 主题 | 一句话说明讨论范围与目标 |
| 状态 | 「进行中」或「已收尾」 |
| 已确认结论 | 结论、依据、受影响的文档或代码 |
| 待确认问题 | 问题、待确认方、影响范围 |
| 已否决方案 | 方案与否决原因 |
| 相关文档 | 上游需求、方案与正式文档链接 |

## 步骤

1. 确认讨论没有承载文档；已有文档时直接更新原文档，不建讨论记录。
2. 在 `docs/drafts/` 建立 `<主题>.md`，写主题、状态与初始待确认问题。
3. 每轮先读文件再讨论；结论形成后立即写入对应章节。
4. 结论稳定后回写正式文档，未决项写入版本 `open-questions.md`。
5. 删除讨论记录，确认正式文档与索引已更新。

## 验证

- 讨论存在对应的 `docs/drafts/<主题>.md`，每轮结论都已落盘。
- 文件只有结论、依据与待确认项，无对话复述与重复内容。
- 收尾后讨论记录已删除，结论可在正式文档中找到。
- 未决事项已写入版本 `open-questions.md`。
