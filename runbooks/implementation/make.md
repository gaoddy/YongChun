# Runbook：Make 构建入口

## 适用场景

- 需要构建、测试、静态检查、生成或启动本地环境时，优先使用仓库的 `make` 入口，不手写等效命令。

## 规则

- 构建、测试、检查、生成、迁移与本地启动各至少有一个目标；缺哪个先补到 `Makefile` 再使用。
- 目标名保持稳定，CI 与本地执行同一套目标，不设「CI 专用脚本」。
- 目标必须幂等、可重复执行，不依赖个人本地状态；需要依赖时自行拉起并等待就绪。
- 失败时输出末尾错误并以非零状态退出，不吞掉退出码，不跳过失败目标。
- 输出量大的目标限制在 8,000–16,000 字节，日志与测试优先查看末尾内容。
- 无参数执行 `make` 输出目标帮助。

## 常用目标

| 目标 | 用途 |
| --- | --- |
| `make <构建目标>` | 构建产物与输出位置 |
| `make <测试目标>` | 端到端测试范围与真实依赖 |
| `make <检查目标>` | 静态检查、格式与类型检查 |
| `make <生成目标>` | 契约或协议生成物 |
| `make <迁移目标>` | 数据库迁移入口 |
| `make <运行目标>` | 本地服务与依赖启动 |

- 目标命名与项目其他约定一致（如 `build`、`test`、`lint`、`generate`、`migrate`、`dev`）；新增目标必须在本表登记。

## 步骤

1. 确认任务对应的目标与预期产物。
2. 在仓库根目录执行 `make <目标>`，记录输出与退出状态。
3. 失败时先读错误与末尾日志，按[问题排查](../problems/troubleshooting.md)定位根因后再重试。
4. 新增或调整目标时，同步更新 `Makefile` 与本 runbook。
5. 交付前执行完整验证目标，确认全部通过。

## 验证

- 目标退出状态为 0。
- 产物路径与文档一致。
- 新增目标已在 `Makefile` 与本 runbook 登记。
- CI 与本地执行的目标一致，无未登记的手写命令。
