# Runbook：版本文档结构

## 适用场景

- 建立或调整版本文档，确认版本目录内的文件形式、命名与生命周期。
- 版本推进的流程见[版本开发](../../version/version-development.md)、[需求变动](../../version/requirement-change.md)、[缺陷修复](../../version/bugfix.md)、[任务计划](../../version/plan.md)；本文只规定文档形式。

## 前置读取

- [文档结构](docs-structure.md)

## 版本目录

```text
docs/versions/<版本>/
├── README.md              版本概览、能力清单与导航
├── open-questions.md      本版本全部未确认事项（必须存在）
├── scope.md               范围与排除项（按需）
├── product/               版本产品基线：本版本的完整产品定义
├── technical/             版本技术基线：以上一版本契约为基线的技术方案
├── update/                基于版本的需求变动，每个需求一个目录，只保留未实现部分
│   └── <YYYY-MM-DD>-<slug>/
│       ├── product.md     产品改动
│       └── technical.md   技术实现方案
├── bugfix/                缺陷修复，每个缺陷一个目录，只保留未修复部分
│   └── <YYYY-MM-DD>-<slug>/
│       └── bugfix.md      现象、根因、影响范围、修复方案与验证方式
└── plans/                 任务计划，每个 task worktree 一个目录，合并前删除
    └── <分支名>/
```

- 目录结构固定；调整前先确认[版本开发](../../version/version-development.md)的流程是否需要同步。
- 版本内文档只描述本版本，不链接或引用后续版本；后续版本可以引用前面版本。
- 未实现的版本定义与需求变动只写入 `docs/versions/<版本>/`；`docs/product/`、`docs/technical/` 只描述当前代码已实现的状态。

## 文件清单

| 文件 / 目录 | 职责 | 创建时机 | 删除时机 |
| --- | --- | --- | --- |
| `README.md` | 版本主题、目标、能力清单、状态与文档导航 | 建立版本 | 不删除 |
| `open-questions.md` | 本版本全部未确认事项 | 建立版本（必需） | 不删除 |
| `scope.md` | 范围与排除项及原因 | 需要界定边界时 | 不删除 |
| `product/` | 版本产品基线（目标形态） | 产品规则确认后 | 版本完成 |
| `technical/` | 版本技术基线（目标形态）；架构选定前含方案候选，选定后只保留选定方案 | 架构方案生成后 | 版本完成 |
| `update/` | 逐项需求变动，只保留未实现部分 | 有新需求时 | 全部实现后删除目录 |
| `bugfix/` | 缺陷修复记录，只保留未修复部分 | 有缺陷时 | 修复完成后删除目录 |
| `plans/` | 任务计划，随任务分支提交 | 任务开始时 | 合并前删除 |

## 版本文档职责

- `README.md` 写版本主题、目标、能力清单、当前状态（规划中 / 开发中 / 已完成）与文档导航；不复制 `product/`、`technical/` 的内容。
- `open-questions.md` 必须存在；没有待确认项时写明「当前无待确认项」。
- `scope.md` 只写本次包含与明确排除的内容及原因，不写功能规则与实现方案。
- `product/`、`technical/` 是版本基线，描述本版本的目标形态；状态标注为「方案未实施」。
- 架构方案候选 `technical/architecture-options.md` 标注「待选择」，用户选定后只保留选定方案并转为技术基线。
- 版本基线与 `docs/product/`、`docs/technical/` 的边界见[文档结构](docs-structure.md)：基线写目标形态，已实现状态写 `docs/`。
- 文件命名、状态标注格式与索引更新按[文档结构](docs-structure.md)执行。

## 待确认项 `open-questions.md`

- 记录本版本未确认的全部事项：产品决策、技术待定、UI 待设计，以及实现中发现的冲突、遗留与需要另定的接口或参数。
- 每条写清：问题、影响范围、待谁确认、来源链接（需求目录、缺陷目录或计划）。
- 由需求变动产生的条目注明来源需求并链接对应 `update/` 目录。
- 事项确认后从文件移除，结论写入对应的 `product.md` / `technical.md` 与版本基线；已实现结论直接写入 `docs/product/`、`docs/technical/`。
- 不在需求、缺陷或计划目录内另建待确认文件，统一收敛到版本根目录。

## 需求变动 `update/`

- 路径：`update/<YYYY-MM-DD>-<slug>/`，日期取需求建立当天；slug 用小写英文与 `-`，表达需求主题，不用版本号、人名或「fix」「update」这类无信息词。
- 目录内最多两份文件，至少存在一份：
  - `product.md`：产品改动。
  - `technical.md`：技术实现方案，按端分节。
- 状态：`product.md` 首行为「待确认」或「已确认」；`technical.md` 首行为「待确认」或「方案未实施」。
- 一个需求一个目录；同一需求在原目录内更新，不新建副本；纯技术改动只有 `technical.md`。
- 只保留未实现内容：已实现部分回写后删除，全部实现后删除整个目录。
- 不在需求目录内另设 `open-questions.md` 或待确认章节。

## 缺陷修复 `bugfix/`

- 路径：`bugfix/<YYYY-MM-DD>-<slug>/`，日期取记录当天；一个缺陷一个目录，后续调整在原目录更新。
- `bugfix.md` 的章节结构：

| 章节 | 内容 |
| --- | --- |
| 状态 | 首行标注「修复中」或「待验证」 |
| 现象与复现 | 错误表现、稳定复现步骤、触发频率、影响的版本与环境 |
| 影响范围 | 受影响的用户、数据、接口与业务链路；是否已产生脏数据 |
| 根因 | 根因所在层与具体位置（文件、函数、配置、数据），附支持结论的证据 |
| 修复方案 | 修复层次、修改端、范围与兼容处理 |
| 验证方式 | 失败用例、回归点、需要检查的日志或数据 |

- 只保留未修复内容：修复完成并回写后删除目录；版本完成时 `bugfix/` 为空。
- 未确认的修复方案写入版本 `open-questions.md`，不在 `bugfix.md` 保留备选。

## 计划 `plans/`

- 路径：`plans/<分支名>/`，分支名中的 `/` 替换为 `-`；一个 task worktree 一个目录。

| 路径 | 职责 |
| --- | --- |
| `index.md` | 任务目标、关联 `update/` 需求目录、分支与 worktree、当前阶段与各阶段确认状态 |
| `task-plan.md` | 任务拆分、依赖关系、并行与串行顺序、每个任务的文件边界与验证方式 |
| `tasks/<task-id>.md` | 一个任务一个文件：输入、产出、文件边界、验证方式与完成标准 |

- `tasks/<task-id>` 与 `task-plan.md` 的编号一致，例如 `T01-baseline.md` 对应 `T01`；新增、拆分或取消任务时两处同步。
- 计划可随任务分支提交；完成任务后、合并前删除，只删当前任务目录，不处理历史目录。

## 版本完成

- 确认 `docs/product/`、`docs/technical/` 已覆盖本版本基线，且 `update/`、`bugfix/` 为空。
- 删除版本内的 `product/`、`technical/` 基线。
- 保留 `README.md` 与 `open-questions.md` 作为版本记录，并在 `docs/versions/README.md` 更新版本状态。
- 版本目录结构与索引同步更新，规则见[文档结构](docs-structure.md)。

## 步骤

1. 建立版本目录，按文件清单创建必需文件。
2. 产品规则确认后写 `product/`；技术方案确认后写 `technical/`，均标「方案未实施」。
3. 需求、缺陷、计划按各自流程建立，文件形式按本文对应的章节。
4. 随实现删除已实现或已修复的内容。
5. 版本完成后删除版本基线、保留版本记录并更新索引。

## 验证

- 文件清单齐全，命名、目录与状态标注符合本文。
- 基线只含目标形态，未混入已实现状态，不引用后续版本。
- `update/`、`bugfix/`、`plans/` 无残留已实现内容。
- 版本完成后版本内基线与空目录已删除，索引与状态已更新。
