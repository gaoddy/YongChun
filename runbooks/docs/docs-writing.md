# Runbook：文档写作

## 适用场景

- 撰写或修改 `docs/` 下文档的内容、表述与状态标注。
- 文档的目录组织与内部结构见[文档结构](structure/docs-structure.md)。

## 写作规则

- 文档必须与本仓库现状一致，不能照搬其他仓库的命令、目录或流程；命令、路径、字段必须能在仓库中核实。
- 只描述当前状态或已确认的目标，明确标注「已实现」「方案未实施」「待确认」；不把推测写成现有功能。
- 一段一个主题，先结论后细节；规则用陈述句，一条一句，不用「优化」「友好」「完善」等无法判定的表述。
- 术语全文统一，首次出现时给出定义；同一概念不在文档中换用同义词。
- 描述行为时写清触发条件、结果与例外，能被测试或人工验收判定。
- 不写决策过程、备选方案、对比分析或「曾经如何」；结论直接写进承载它的文档。
- 版本内文档以上一版本契约为基线，只记录增量与变更，不复制基线内容。
- 引用其他文档用相对链接，不复制其内容；实现细节以源码路径为准，不在文档中复述；数据结构文档按[文档结构](structure/docs-structure.md#数据结构文档)同步原始定义。
- 中文正文使用全角标点；技术标识、命令、路径与字段保持原样，不翻译。

## 步骤

1. 确认文档归属与状态（见[文档结构](structure/docs-structure.md)），选择对应目录与文件。
2. 按写作规则撰写，逐条核对命令、路径、字段与接口名。
3. 标注状态与范围说明，补充相关文档链接。
4. 按文档结构的要求更新索引与入链。
5. 按[文档回写](docs-sync.md)同步删除已实现的需求记录。

## 验证

- 内容与代码现状一致，已实现文档中不含规划内容。
- 每条规则可验收，无模糊表述与营销词。
- 术语统一，命令、路径、字段可在仓库核实。
- 状态标注正确，相对链接有效，索引已登记。
