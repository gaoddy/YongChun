# Runbook：新增接口

## 适用场景

- 新增或修改 `/api/v1/...` 接口、请求或响应字段。

## 前置读取

- [服务端分层](server/layering.md)
- [服务端运行](server/runtime.md)
- [可观测性](../problems/observability.md)

## 服务端实现约定

- 新接口统一走 `/api/v1/...` 前缀。
- 健康检查固定为 `/healthz`（存活）与 `/readyz`（就绪）。
- 接口文档在 `<文档地址>`；新增或变更接口时同步更新。
- 接口、响应字段、注释或 OpenAPI 类型变化后，在当前 task worktree 执行 `<生成命令>`，生成物与源契约一起提交。
- handler 在本接口内只做参数解析、鉴权入口、状态码映射和接口注释；业务规则、事务编排与跨层依赖按[服务端分层](server/layering.md)执行。
- 新接口的错误码、关键日志字段与指标按[可观测性](../problems/observability.md)同步定义。

## 契约约束

| 项 | 约定 |
| --- | --- |
| URL 与版本 | 资源用复数名、kebab-case，动作由 HTTP 方法表达，不在路径写动词；统一前缀 `/api/v1`，破坏性变更升级前缀 |
| 方法与状态码 | GET 查询、POST 创建、PUT/PATCH 更新、DELETE 删除；201 创建成功、204 无返回体、400 参数错误、401 未认证、403 无权限、404 不存在、409 冲突、422 业务校验失败、429 限流、5xx 服务端错误 |
| 响应形态 | 成功与错误使用统一结构 `<响应结构>`；错误包含稳定错误码、可展示消息与定位字段；错误码不复用、不改语义 |
| 分页 | 列表统一使用 `<分页方式>`，固定默认页大小与上限；排序键稳定，不用大偏移量翻页 |
| ID 与时间 | 对外 ID 用字符串，不暴露自增主键；时间统一 RFC 3339 UTC 字符串，客户端负责本地化 |
| 认证 | `Authorization: Bearer <token>`；权限在 application 或 domain 校验，不只在网关或 handler |
| 幂等 | 创建、支付类写接口支持 `Idempotency-Key`，重复请求返回首次结果；其他写接口说明重复调用的后果 |
| 契约演进 | 开发阶段允许同一版本内前后端同批更新；上线后只新增字段与可选参数，重命名、删除或改语义走新版本前缀 |
| 接口文档 | 契约、注释与生成物同源，生成物随代码提交，文档可访问 |
| 限流与防刷 | 按用户与 IP 双维度限流；超限返回 429 与 `Retry-After` |
| CORS 与 Origin | 只允许白名单来源；携带凭证时不用 `*` |
| 上传与内容安全 | 限制大小与类型，按内容而非扩展名校验；文件名不参与存储路径；上传后异步扫描 |

## 步骤

1. 在版本 `update/<需求>/technical.md` 写明接口契约变更（路径、字段、错误码、分页与幂等），确认后再实施。
2. 在 `domain` 定义业务规则与端口，在 `application` 编排事务，在 `handler` 只做参数解析与状态码映射。
3. 修改接口定义与注释，执行 `<生成命令>`；生成物与源契约一起提交。
4. 补充或更新端到端测试，覆盖成功、参数错误、权限拒绝与幂等重复请求。
5. 同步更新 `docs/technical/` 的接口契约文档与错误码说明。

## 验证

- 生成命令无差异：`<生成命令>`
- 端到端测试通过：`<e2e 入口>`
