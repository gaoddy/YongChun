# Runbook：gRPC 接口

## 适用场景

- 设计或调整 gRPC 服务的 proto 契约、流式接口、错误与兼容演进规则。
- 通用规则与协议选择见[接口契约](contract.md)；新增或修改接口的实施步骤见[新增接口](../new-api.md)。

## 前置读取

- [接口契约](contract.md)

## 规则

- 服务契约以 `.proto` 为唯一来源，生成物随源契约提交；包名带版本，服务与方法用名词短语。
- 每次调用设置 deadline；流式接口写明流方向（单向 / 双向）、生命周期、取消与背压处理。
- 错误使用 status code 与稳定的 error details；业务失败不放进 OK 响应。
- 元数据只传鉴权与追踪 ID，不放大客户端传入的元数据。
- 兼容演进只新增字段与枚举值，不改变字段语义；保留字段编号不复用，删除字段使用 `reserved`。
- 流式接口写明消息速率上限、队列上限与超限处理，不无限缓冲。

## 步骤

1. 确认调用方、方法类型（一元 / 流式）与超时要求。
2. 定义 proto 包版本、消息字段、错误码与元数据约定。
3. 定义流式接口的取消、背压与重试语义；偏离规范时写入版本 `technical.md` 并取得确认。
4. 按[新增接口](../new-api.md)完成契约、生成、测试与文档。

## 验证

- proto 契约与生成物一致，包名与服务命名符合规范。
- 每次调用有 deadline，流式接口有取消与背压处理。
- 错误使用 status code 与稳定 details，未混入 OK 响应。
- 字段编号未复用，兼容演进规则成立。
