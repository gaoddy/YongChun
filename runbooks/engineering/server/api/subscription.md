# Runbook：消息订阅接口

## 适用场景

- 设计或调整异步消息的生产、订阅、确认、重试与死信规则。
- 通用规则与协议选择见[接口契约](contract.md)；新增或修改接口的实施步骤见[新增接口](../new-api.md)。

## 前置读取

- [接口契约](contract.md)

## 规则

- 消息订阅只用于异步事件与解耦；需要同步结果的调用使用[HTTP](http.md)或 [gRPC](grpc.md)。
- 主题与队列名称表达业务事件，版本写在主题名或消息 schema 中；新增版本不改旧主题语义。
- 每个主题写明生产者、消费者、分区键与顺序范围；同一聚合根的事件使用同一分区键保持顺序。
- 投递语义明确为至少一次或至多一次；至少一次时消费方必须幂等，以事件 ID 或业务键去重。
- 消费确认在业务处理成功后；失败按退避重试，超过上限进入死信队列并告警，禁止无限重试。
- 消费组并发数与分区数匹配；监控积压、消费延迟与失败率，积压超过阈值告警。
- 消息 schema 兼容演进：只新增字段，未知字段忽略；破坏性变更新建主题或版本，不原地修改。
- 事件不可变，修正以新事件表达，不修改已发布事件。

## 步骤

1. 确认事件来源、消费者与允许的延迟。
2. 定义主题、分区键、投递语义与幂等键。
3. 定义确认、重试、死信与积压告警；偏离规范时写入版本 `technical.md` 并取得确认。
4. 按[新增接口](../new-api.md)完成契约、测试与文档。

## 验证

- 主题、分区键与顺序范围明确，同一聚合根保序。
- 投递语义与消费幂等一致，重复消息不会产生重复副作用。
- 重试有上限，死信有处理人与告警。
- schema 演进兼容，事件不可变。
