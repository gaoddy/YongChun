# Runbook：数据访问

## 适用场景

- 设计或调整服务端数据访问规则。

## 前置读取

- [服务端分层](layering.md)

## 规则

- 真相源：数据库是唯一真相源，缓存只做加速，可随时清空并从库重建。
- 事务边界：一次请求一个事务，在 application 层显式开启；跨表写入在同一事务内完成，不在循环中提交。
- 查询：列表与过滤查询必须有可用索引，索引规划见[数据库表规划](../database/table-design.md)；禁止 N+1；分页与排序键形态见[HTTP 接口](api/http.md)。
- 锁与并发：写路径明确锁粒度与冲突处理；高冲突场景用幂等键或唯一约束兜底，不用重试掩盖竞态。
- 缓存键：`<业务>:<对象>:<id>` 结构，带版本前缀便于整体失效；写库后先更新库再删除缓存，不先写缓存。

## 步骤

1. 确定真相源与事务边界：数据库为唯一真相源，一次请求一个事务。
2. 为列表、过滤与排序查询确认可用索引，分页按接口契约执行。
3. 写路径明确锁粒度、冲突处理与幂等键。
4. 设计缓存键与失效顺序：写库后先更新库再删缓存。
5. 按验证项检查查询、事务与缓存行为。

## 验证

- 缓存可随时清空并从库重建，业务结果不变。
- 跨表写入在同一事务内完成，循环中无提交。
- 列表与过滤查询命中索引，无 N+1。
- 写路径有明确锁粒度或幂等兜底，竞态不以重试掩盖。
- 缓存键带业务、对象、ID 与版本前缀，写库后先更新库再删缓存。
