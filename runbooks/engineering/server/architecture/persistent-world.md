# Runbook：大世界 MMO 架构

## 适用场景

- 设计角色长期在线、世界持久、按 AOI 广播的大世界 MMO 服务端架构。
- 适用于单地图承载大量玩家、需要分线与实例承载、存在跨地图与跨服边界且世界对玩家只读的持久世界；不适用于玩家可修改世界的沙盒、单场实时对局与回合请求-响应，这些回到[服务架构方案生成](index.md)按场景路由选择分册。

## 规则

### 同步模型

- 服务端持有权威世界状态，按 AOI 只向玩家广播其关注范围内的实体与事件；客户端不做权威模拟，只做表现层插值。判定：客户端上报的坐标、掉落或战斗结果被服务端采信为权威，或向全场景无条件广播，均不属于本模型。
- 实体状态驻留场景实例内存，按固定 tick 推进；落库采用定期快照加关键事件日志，异步执行，不阻塞 tick。判定：方案要求每次状态变化同步写库，或进程内状态没有任何恢复手段，均视为反例。
- AOI 以玩家坐标为中心按半径或网格划分：进入范围下发完整实体状态，离开范围下发移除标记。判定：实体离开 AOI 后仍持续下发状态，或重新进入时只补增量而无完整基线，均为同步错误。

### 世界结构

- 分层固定为四段：无状态网关负责连接、鉴权、编解码与转发；场景服承载地图实例（含分线与副本实例）与 tick 循环；世界服或全局服承载跨场景的全局状态（排行榜、全局经济、社交关系、世界事件）；跨服边界用独立路由与消息协议连接。判定：网关内存保存玩家场景状态，或场景服直接持有跨服全局数据，说明边界画错。
- 分片键必须写明粒度：按地图分片（同一地图的实例集合落在同一场景服分组）、按线分片（同地图不同线落到不同实例）、按实例分片（单个实例为最小调度单元）。方案必须写明每个分片键用于哪一层，不得只写「按玩家 ID 哈希」。
- 玩家进入世界由网关按当前场景键路由到场景服；跨地图迁移由世界服协调，先落地目标实例成功再切换连接。判定：路由依赖网关本地缓存且网关重启后无法重建，为反例。

### 候选架构差异

- 分线扩实例与地图分片是两套独立扩容手段，方案必须分别写明触发条件：分线扩实例的触发指标是单地图在线人数与单实例 tick 耗时；地图分片的触发指标是场景服分组的实例数、连接数与出网带宽。两者不得合并成「横向扩展」一句。
- 两套手段的最小调度单元与迁移语义不同：分线扩实例以实例为单元，已有玩家留在原线，新玩家进入新线；地图分片以整张地图的实例集合为单元，进行中实例按排期迁移，不逐玩家迁移。
- 三种方案必须在以下维度给出实质不同的形态：场景服打包方式（单进程承载多地图实例与按地图或实例独立进程）、分线调度（静态分线与按负载动态分配）、跨服一致性（单一全局库与按区域分库加跨服网关）、广播通道（UDP 与基于 TCP 的 WebSocket）。判定：上述四项中有三项以上取同一形态，视为只换技术名称。

### 容量指标

- 在线连接数：`C = 峰值在线玩家数 × 每玩家连接数`，单位「连接」；每玩家连接数默认为 1，需要独立世界服通道时计入第二条，上下行不共用该指标。
- AOI 下行带宽：`单玩家下行速率 = f_tick × N_aoi × S_entity`，单位 B/s；其中 `f_tick` 为广播 tick 频率（次/s），`N_aoi` 为 AOI 内实体数（取峰值，个），`S_entity` 为单实体单次状态包字节（B）。`场景实例出网 = Σ单玩家下行速率 + 事件与跨服信令`，与实例网卡和集群配额比较。
- tick 预算：`单实例玩家上限 = floor(T_budget / t_player)`；`T_budget` 为单 tick 计算与广播时间预算（ms），`t_player` 为单玩家每 tick 处理与广播耗时（ms/玩家）。方案必须给出 `f_tick` 与 `T_budget` 的具体取值。
- 单线玩家上限：`单线玩家上限 = min(玩法单线上限, 单实例玩家上限)`；`玩法单线上限` 由玩法设定（如同一地图同时可见或同屏交互的期望人数），不源于 tick 预算，`单实例玩家上限` 来自上面的 tick 预算。取两者较小值，保证分线后的实例同样不超 tick 预算；方案必须给出 `玩法单线上限` 的取值依据。
- 场景实例数与分线数：按地图分别计算。`分线数 = ceil(该地图峰值在线玩家数 / 单线玩家上限)`；`实例数 = 分线数 + 副本实例数`，副本实例数按该地图同期副本峰值单独核算，无副本的地图取 0、此时实例数等于分线数；再按地图求和。不按全服总人数均分，不把实例数与分线数当作两个互不相干的指标重复推导。
- 存档写入：`存档写 QPS = 峰值在线玩家数 / 存档周期(s)`，单位 次/s；日写入量按峰值上界估算，`日写入量 = 峰值在线玩家数 × 86400 / 存档周期(s) × 单存档字节 × 写放大系数`，单位 B/日，写放大系数含版本与索引开销。
- 判定：每个方案能复算连接数、AOI 下行带宽、单实例玩家上限、实例数、存档写入五个量，给出 `单线玩家上限` 取值依据与 `实例数 = 分线数 + 副本实例数` 的推导关系，并标注假设与峰值集中系数；缺少任一项视为容量推算不完整。

### 平滑扩容

- 网关无状态：不保存玩家场景与 AOI 状态，直接水平扩展；网关重启后玩家重连，由世界服按场景键重新路由。
- 分线扩容：单地图在线超过阈值时新开一条线并分配新实例；已有玩家留在原线，只有原实例故障或跨线组队时才迁移。
- 地图分片：把整张地图的实例集合迁到新场景服分组，扩充分组数与每分组场景服数量；迁移以实例为单位，进行中实例按排期迁移或随重启迁回。
- 跨服边界：跨服活动与跨服匹配按独立服务扩展，不把跨服流量压到世界服单点；跨服状态以活动实例为一致性边界。
- 判定：扩容期间进行中玩家不丢状态，新玩家落到新实例；每项扩容的触发指标与阈值写入方案，并能对应到具体监控量。

### 常见陷阱

- 热点地图：单地图人口集中导致单实例 tick 超时。反例是按全服平均在线估算实例数；规避要求逐地图核算峰值，并设置单线人数上限与进入排队。
- 跨线交易与组队一致性：队伍成员分布在不同线或实例，交易与组队状态各自为政。要求组队与交易状态按队伍 ID 归属世界服或单一权威服，跨线操作由归属方串行确认；反例是两侧实例各自扣减、依赖事后对账。
- 重连回到原线：断线重连被重新分配到新线，队伍与私有场景（家园、副本）状态丢失。要求会话令牌携带场景键与实例 ID，重连优先回原实例；实例已不存在时按方案定义的降级路径处理，不得静默换线。
- 世界事件广播风暴：全服公告、Boss 刷新或天气事件向全部玩家广播，单 tick 出网被打满。要求世界事件按 AOI 或频道过滤，全服广播走异步分级通道并限速；反例是事件与玩家状态共用同一 tick 广播通道。
- 存档写入放大：每次状态变化都写库，或大量玩家在同一时刻存档。要求按玩家错峰、批量合并写，并给单玩家存档周期设下限；反例是 `存档写 QPS` 等于在线玩家数乘以状态变化频率。

## 步骤

1. 按[服务架构方案生成](index.md)读取产品需求、产品描述、用户规模与现有实现，确认属于角色长期在线、世界持久、按 AOI 广播的大世界 MMO；不属于时回到入口按场景路由选择分册。
2. 按入口的三种方案要求与输出位置生成方案，只展开 MMO 差异部分：同步模型、四段世界结构、分片键、分线扩实例与地图分片两套扩容手段的触发条件、候选架构差异维度、逐地图峰值分布。
3. 按「容量指标」公式为每个方案逐地图计算连接数、AOI 下行带宽、单实例玩家上限、实例数与分线数、存档写入量，记录假设与峰值集中系数，写入该方案的平滑扩容部分。
4. 为每个方案写明网关无状态、分线扩容、地图分片、跨服边界与断线重连回到原实例的路径，以及「常见陷阱」的规避方式；给出各项扩容的触发指标与阈值。
5. 按入口要求给出对比表与推荐方案，取得用户选择后按[服务端方案实现](../implementation.md)细化选定方案。

## 验证

- AOI 内广播正确：进入范围的实体在首个 tick 内收到完整状态，离开范围后不再收到其更新；重新进入时先收到完整基线，不出现残留增量。
- 跨线操作有明确一致性策略：组队、交易与跨线传送由归属方串行确认，并发跨线交易压测无重复扣减与丢单。
- 断线重连回到正确实例：重连后恢复原线、原实例与私有场景状态；原实例不存在时按方案定义的降级路径处理，不静默换线。
- 广播带宽低于阈值：按公式复算的峰值下行带宽低于实例网卡与集群配额阈值，并留有峰值集中系数余量。
- tick 稳定：单实例在方案给出的 `N_aoi` 峰值与 `f_tick` 下，实测 tick 耗时低于 `T_budget`。
- 存档写入不阻塞 tick：存档异步执行，落库延迟不计入 tick 时间预算，存档 QPS 与写放大系数可复算。
- 每个方案写明五个容量量、两套扩容的触发条件与分片键；三种方案在候选差异维度上存在实质差异，且均覆盖全部产品需求与最终用户规模。
