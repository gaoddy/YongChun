# Runbook：沙盒架构

## 适用场景

- 设计玩家可修改世界、按区块加载卸载并持久化的沙盒服务端架构。
- 适用于世界数据由玩家写入、以区块为单位持久化、存在 UGC 与权限控制的产品；不适用于玩家只读的持久大世界、单场对局与回合请求-响应，这些回到[服务架构方案生成](index.md)按场景路由选择分册。

## 规则

### 同步模型

- 区块或区域是加载、卸载与同步的最小单元：服务端按玩家位置确定视距内的区块集合，进入范围加载并下发完整区块状态，离开范围卸载并从后续同步中移除。判定：以单个方块或单条修改为加载单元，或离开范围后仍持续下发该区块更新，均不属于本模型。
- 玩家修改以区块增量同步：同区块内的修改按修改标识与版本号合并后广播给关注该区块的玩家，客户端据此回放；修改同时进入该区块的待落盘队列。判定：修改以全量区块重发，或只广播给发起者本地的其他客户端，均为反例。
- 区块卸载前必须完成落盘：解锁流程为「停止接受该区块新修改 → 排空待落盘队列 → 确认持久化成功 → 释放内存」。判定：卸载时直接丢内存或异步落盘失败后仍释放内存，视为数据丢失路径；落盘失败必须保留区块并告警，不进入释放。

### 权限与 UGC

- 世界复制、访客权限与破坏防护在服务端校验，客户端提交的角色、权限与目标区块一律不作为授权依据。判定：以客户端上报的「我是管理员」或本地世界文件为准放行，为反例。
- 修改校验同时覆盖「谁能改」与「能否改」：前者按世界归属、角色权限与访客规则判定，后者按保护区、插件规则与破坏防护判定；两项均通过才写入。方案必须写明权限数据存放在哪一层并由谁串行判定。判定：只校验角色权限而不校验保护区与破坏防护，或在客户端先行判定、服务端只做格式校验，均为反例。
- UGC 内容隔离与限流：玩家上传的资源、脚本与配置按世界隔离存储，加载在前置校验（体积、类型、解析）之后进行；单世界与单玩家的 UGC 写入、上传与执行分别设定配额与速率上限。判定：UGC 与静态地形共用同一可写命名空间，或无配额直接执行上传内容，均视为隔离失败。

### 候选架构差异

- 三方案围绕三段拆分给出不同形态：世界服承担世界元数据、权限、世界复制与路由；区块服或实例承担区块加载、修改接收与增量广播；对象存储承担静态地形与动态修改的持久化。判定：任一方案把三段压成单进程且未说明分段理由，或三方案只在语言与框架上不同，视为未给出实质差异。
- 静态地形与动态修改分离存储：静态地形按世界版本生成一次、只读分发；动态修改按区块 ID 存储增量。判定：每次启动重写静态地形到可写库，或动态修改与静态地形混存导致全量重写，均为反例。
- 三方案必须在以下维度给出可区分的取舍，并写明各自适用前提：区块服的承载方式（单进程多区块与按区块集合独立实例）、世界实例的隔离方式（共享区块服与按世界独立实例）、修改落盘方式（同步双写与队列异步落盘加定期快照）、UGC 存储（对象存储与独立内容服务）。上述四项中三项以上取同一形态，视为只换技术名称。

### 容量指标

- 并发区块加载数：`L = 峰值在线玩家数 × 每玩家加载区块数 / 重叠系数`，单位「区块」；`每玩家加载区块数 = (2R + 1)^2`，`R` 为视距半径（区块），`重叠系数` 为共享度，表示同一区块同时被多少个玩家加载，取值 `1 ≤ 重叠系数 ≤ 峰值在线玩家数`。上界对应所有玩家视距完全重合：全部聚集时 `重叠系数 = 峰值在线玩家数`，`L = 峰值在线玩家数 × 每玩家加载区块数 / 峰值在线玩家数 = 每玩家加载区块数`，唯一区块数退化为单个玩家的加载区块数；下界 `1` 表示玩家彼此不相邻、无共享。系数按实际聚集分布取值并标注依据：均匀分散取 `1`，街区或活动点聚集按实测平均同区块玩家数取值，全部聚集取 `峰值在线玩家数`。判定：直接用玩家数乘视距半径而无重叠系数，或把加载数当作不共享的独立区块数，均为口径错误。
- 修改写入 QPS：`W = 峰值在线玩家数 × 每玩家每秒修改次数 × 写放大系数`，单位 次/s；`每玩家每秒修改次数` 按玩法峰值场景取值并在方案中标注依据，`写放大系数` 含索引、版本与合并开销。
- 区块存储增长：`日增长 = 日修改玩家数 × 每人每日修改区块数 × 单区块修改记录字节 × 写放大系数`，单位 B/日；`年增长 = 日增长 × 365`。方案必须区分静态地形存储（一次性，按世界数 × 单世界字节）与动态修改存储（按上式增长）。
- 广播带宽：`单玩家下行速率 = f_sync × N_delta × S_delta`，单位 B/s；`f_sync` 为增量同步频率（次/s），`N_delta` 为玩家当前关注区块内每次同步下发的修改条数（条/次），`S_delta` 为单条修改包字节（B）。三个因子量纲相乘为 B/s，不得再把 `N_delta` 定义为「每秒条数」与 `f_sync` 重复计秒。`区块服出网 = Σ单玩家下行速率 + 跨区块与落盘信令`，与实例网卡和集群配额比较。
- 世界实例数：`世界实例数 = ceil(峰值并发世界数 / 单实例承载世界数)`；`单实例承载世界数 = floor(M_budget / B_world)`，`M_budget` 为单实例可用内存预算（B），`B_world` 为单世界常驻区块字节（B）。方案必须给出 `M_budget` 与 `B_world` 的取值依据，不得只写「按机器配置」。
- 判定：每个方案能复算并发区块加载数、修改写入 QPS、区块存储增长、广播带宽与世界实例数五个量，标注假设、峰值集中系数与重叠系数；缺少任一项视为容量推算不完整。

### 平滑扩容

- 区块是分片单元：以区块 ID 或区块集合为键分配到区块服，扩容时迁移区块集合而非迁移玩家；区块迁移必须在新归属完成落盘后切换路由。判定：以玩家 ID 作为区块数据的分片键，导致同一区块被多实例写入，为反例。
- 世界实例独立部署：每个世界或世界组按世界实例数独立扩缩，单个世界的高负载不扩散到其他世界；世界实例与区块服的扩缩触发指标分开定义。
- 静态与动态数据分离扩容：静态地形按世界版本只读分发，用 CDN 或对象存储扩展；动态修改按区块分片扩展写入与存储能力。两者不得共用一个扩容触发指标。
- 判定：扩容期间进行中玩家不丢修改，迁移区块在切换前完成落盘；每项扩容给出触发指标与阈值，并能对应到具体监控量。

### 常见陷阱

- 区块写放大：把单条修改写成整区块覆盖，或按固定周期全量重写区块。要求按修改增量落盘并合并，写放大系数实测取值；反例是 `修改写入 QPS` 等于在线玩家数乘修改频率后仍按整区块写入。
- 跨区块边界的修改同步：修改影响相邻区块（红石、流体、结构）时只更新本区块，导致边界两侧不一致。要求为跨区块修改定义归属区块与传播规则，边界两侧同版本原子提交；反例是两侧各自写入、依赖客户端表现掩盖差异。
- 恶意破坏与复制：利用世界复制、回档或权限漏洞复制物品或绕过保护。要求世界复制按快照版本生成且不复制可交易实体，破坏行为在服务端按权限与速率双重校验；反例是把复制与恢复操作完全交给客户端本地执行。
- 世界版本迁移：静态地形升级或插件规则变更导致旧修改与新地形不匹配。要求世界记录地形版本与修改格式版本，迁移前备份并离线校验，迁移失败可回退到旧版本；反例是升级时直接丢弃无法解析的修改。
- 卸载丢数据：区块卸载、实例迁移或进程重启时未完成落盘。要求卸载前排空队列并确认持久化，迁移以目标落盘成功为切换条件，进程退出执行优雅停机；反例是把落盘挂在进程退出回调且不检查结果。

## 步骤

1. 按[服务架构方案生成](index.md)读取产品需求、产品描述、用户规模与现有实现，确认属于玩家可修改世界、按区块加载卸载并持久化的沙盒；不属于时回到入口按场景路由选择分册。
2. 按入口的三种方案要求与输出位置生成方案，只展开沙盒差异部分：区块同步与卸载落盘流程、权限与 UGC 校验、三段拆分与静态/动态分离存储、候选架构差异维度、世界与区块的峰值分布。
3. 按「容量指标」公式为每个方案计算并发区块加载数、修改写入 QPS、区块存储增长、广播带宽与世界实例数，记录假设、峰值集中系数与重叠系数，写入该方案的平滑扩容部分。
4. 为每个方案写明区块分片、世界实例独立部署、静态与动态数据分离扩容的路径与触发指标，以及「常见陷阱」的规避方式。
5. 按入口要求给出对比表与推荐方案，取得用户选择后按[服务端方案实现](../implementation.md)细化选定方案。

## 验证

- 区块卸载后数据不丢：卸载、进程重启与实例迁移后重新加载区块，修改内容与卸载前一致；落盘失败时区块未被释放并有告警。
- 跨区块边界修改一致：边界两侧相邻区块的修改在同版本内可见，并发跨边界修改压测无单侧生效。
- UGC 隔离与权限生效：访客与无权限角色无法修改受保护区块或读取其他世界的 UGC；越权请求在服务端被拒绝并记录。
- 写入限流触发：单玩家或单世界的修改、上传与执行速率达到配额时被限流，超出部分拒绝且不影响已接受的修改。
- 容量可复算：五个容量量均能按公式与假设复算，重叠系数与峰值集中系数有取值依据。
- 扩容不中断：区块迁移与实例扩容期间进行中玩家不丢修改，新玩家落到新归属。
- 三种方案在候选差异维度上存在实质差异，且均覆盖全部产品需求与最终用户规模。
