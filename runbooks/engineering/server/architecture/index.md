# Runbook：服务架构方案生成

本文件同时作为 `architecture/` 分册入口与索引：本目录以 `index.md` 代替 `README.md` 作为入口与索引，是对[runbook 编写与维护](../../../runbook.md#目录规划)中分册目录须有 `README.md` 规则的例外，其余分册目录仍用 `README.md`；`index.md` 不生成 agent，执行时按「场景路由」选择分册 agent。

## 适用场景

- 项目初始化、新版本或重大需求需要确定服务端架构，架构方向尚未确定时。
- 架构方向已确定、只需细化实现方案时，直接按[服务端方案实现](../implementation.md)执行。

## 场景路由

先按游戏类型与同步形态定位分册，再与通用方案要求合并使用。

| 场景 | 分册 |
| --- | --- |
| 固定 tick、确定性输入广播、需要回放复现 | [实时对战帧同步](realtime-frame-sync.md) |
| 服务端权威实时对战、客户端预测与校正 | [实时对战状态同步](realtime-state-sync.md) |
| 高帧率体育竞技、延迟补偿与观战回放 | [体育竞技](sports-competition.md) |
| 回合请求-响应、服务端校验、异步对战 | [回合制](turn-based.md) |
| 持久大世界、分线分片与 AOI，玩家只读 | [大世界 MMO](persistent-world.md) |
| 玩家可改世界、区块加载与 UGC | [沙盒](sandbox.md) |
| 大地图、定时事件驱动、资源强一致与分区开服 | [SLG 大战略](slg.md) |
| 弱在线、本地计算、云存档与排行 | [休闲与小游戏](weak-online.md) |

同一玩法同时命中多行时，按以下顺序匹配（按此顺序匹配，命中即停）：高帧率、延迟补偿与观战回放 → 体育竞技；玩家可改世界按区块 → 沙盒；持久世界、分线分片与 AOI 且玩家只读 → 大世界 MMO；大地图定时事件驱动与资源强一致 → SLG；回合请求-响应与异步对战 → 回合制；固定 tick 且输入驱动 → 帧同步；服务端权威实时模拟 → 状态同步；其余无实时对局 → 休闲。

通用输入、三种方案要求、输出位置与选择规则见[服务架构方案通用要求](requirements.md)。

## 步骤

1. 按「场景路由」定位分册。
2. 读取对应分册并按通用要求执行。
3. 用户选定后按[服务端方案实现](../implementation.md)细化方案，删除其余候选。

## 验证

- 已按场景路由选定唯一分册。
