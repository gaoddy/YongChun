# Runbook：服务端分层

## 适用场景

- 新增或调整服务端模块、依赖方向、端口与装配方式。

## 前置读取

- [根规则的触发与必读](../../../AGENTS.md#触发)
- [目录结构与命名](../directory-structure.md)

## 规则

### 依赖方向

- handler → application → domain 单向依赖；infrastructure 实现 domain 定义的端口，只被入口引用。
- domain 不导入框架、数据库驱动、HTTP 客户端等具体实现，只定义业务规则与端口。
- application 负责事务边界与跨领域编排，不拼 SQL，不处理 HTTP 细节。
- handler 只做参数解析、鉴权入口与状态码映射，不含业务判断，不直接访问 repository。
- 出现循环依赖视为分层错误：调整职责或端口归属，不新增中间包绕过。

### 装配与生命周期

- 端口由使用方定义；实现按接口在入口统一注册，替换实现（真实 / 测试 / 不同环境）只改装配处，不改调用方。
- 配置读取与资源生命周期只在入口处理；业务层不读取环境变量，不自行创建连接。

### 分层示例

- 在版本 `technical/` 中选一条核心读链路与一条核心写链路，逐层写出调用经过、事务边界与不变量，作为分层落点的示例；链路变化时同步更新。

## 步骤

1. 在版本 `update/<需求>/technical.md` 说明模块职责与依赖方向。
2. 按分层放置代码：domain 定义规则与端口，infrastructure 实现，application 编排，handler 适配。
3. 在入口完成依赖装配，不在调用方直接构造具体实现。
4. 为新模块补一条核心读写链路示例。
5. 调整完成后检查跨层依赖与循环依赖。

## 验证

- 依赖方向符合分层约束，无跨层直接依赖与循环依赖。
- 业务层不读取环境变量、不创建连接，装配只在入口。
- 核心读写链路示例与代码一致。
- 构建、静态检查与端到端测试通过。
