# Runbook：服务端接口

## 适用场景

- 设计或调整服务端接口的契约、协议行为与兼容规则，协议包括 HTTP、WebSocket、gRPC 等。
- 新增或修改具体接口的实施步骤见[新增接口](new-api.md)；本文只规定接口规则，不写实施流程。

## 通用规则

- 契约以代码中的类型定义、注释与 `.proto` / schema 为唯一来源，生成物随源契约提交；不手写与代码不一致的接口文档。
- 每个接口、消息与事件写明用途、调用方、鉴权要求、幂等语义与失败表现。
- 对外标识用字符串，不暴露自增主键；时间统一 RFC 3339 UTC 字符串；金额用最小货币单位整数。
- 兼容演进：开发阶段允许同一批次前后端同批更新；上线后只新增字段与可选参数，重命名、删除或改语义走新版本（HTTP 新前缀、gRPC 新包版本、WebSocket 新消息版本）。
- 错误使用稳定错误码，不复用、不改语义；错误码、日志字段与指标按[可观测性](../../problems/observability.md)同步定义。
- 权限在 application 或 domain 校验，不只在网关或 handler；handler 只做参数解析、鉴权入口与状态码映射，分层见[服务端分层](layering.md)。
- 所有对外接口都有限流；列表与批量接口有分页、条数上限与超时；重复提交有幂等键或明确后果。
- 破坏性变更、删除接口或变更鉴权方式，先写入版本 `technical.md` 并取得确认。

## HTTP

- 统一前缀 `/api/v1`，资源用复数名、kebab-case，动作由 HTTP 方法表达，不在路径写动词；破坏性变更升级前缀。
- 方法：GET 查询、POST 创建、PUT/PATCH 更新、DELETE 删除；201 创建成功、204 无返回体、400 参数错误、401 未认证、403 无权限、404 不存在、409 冲突、422 业务校验失败、429 限流、5xx 服务端错误。
- 成功与错误使用统一结构 `<响应结构>`；错误包含稳定错误码、可展示消息与定位字段。
- 列表统一使用 `<分页方式>`，固定默认页大小与上限；排序键稳定，不用大偏移量翻页。
- 认证使用 `Authorization: Bearer <token>`；创建与支付类写接口支持 `Idempotency-Key`，重复请求返回首次结果，其他写接口说明重复调用的后果。
- 按用户与 IP 双维度限流，超限返回 429 与 `Retry-After`；CORS 只允许白名单来源，携带凭证时不用 `*`。
- 上传限制大小与类型，按内容而非扩展名校验；文件名不参与存储路径，上传后异步扫描。
- 健康检查固定为 `/healthz`（存活）与 `/readyz`（就绪）。

## WebSocket

- 握手时校验身份，不在连接建立后通过消息传递长期凭证；未认证连接在约定时间内断开。
- 消息使用统一信封，至少包含 `type`、`id`、`version` 与 `payload`；未知 `type` 忽略并记录，不断开连接。
- 心跳与超时：服务端主动 ping、客户端 pong，超时断开；客户端重连使用退避策略。
- 重连后按游标或序号恢复状态；明确消息是至少一次还是至多一次，重复消息可被客户端识别。
- 单连接内消息有序；发送队列有上限，超限时按约定丢弃或断开，不无限缓冲。
- 写明单条消息大小上限、分片方式与二进制编码格式。

## gRPC

- 服务契约以 `.proto` 为唯一来源，生成物随源契约提交；包名带版本，服务与方法用名词短语。
- 每次调用设置 deadline；流式接口写明流方向、生命周期、取消与背压处理。
- 错误使用 status code 与稳定的 error details；业务失败不放进 OK 响应。
- 元数据只传鉴权与追踪 ID，不放大客户端传入的元数据。
- 兼容演进只新增字段与枚举值，不改变字段语义；保留字段编号不复用。

## 其他协议

- SSE、消息订阅与长轮询等：写明连接或订阅生命周期、投递语义（至少一次 / 至多一次）、重试与死信、顺序保证与背压。
- 新增协议前先说明现有协议无法满足的原因，并在版本 `technical.md` 记录取舍。

## 步骤

1. 确认协议、调用方与连接或调用方式，选择通用规则与对应协议章节。
2. 逐项核对规则，列出实现必须遵守的项与本项目的例外；例外写入版本 `technical.md` 并取得确认。
3. 规则调整时先改本文，再同步版本 `technical.md` 与受影响的接口文档。
4. 具体接口的新增或修改按[新增接口](new-api.md)执行。

## 验证

- 每个接口都能对应到通用规则与协议章节，无未覆盖的协议行为。
- 项目的例外已记录并获得确认，没有把例外当作默认规则。
- 本文与版本 `technical.md`、接口文档一致，无与实现冲突的旧描述。
- 新增协议已说明现有协议无法满足的原因。
