# Runbook：服务端运行

## 适用场景

- 服务端源码结构、依赖、部署形态与本地运行环境的修改或排查。

## 前置读取

- [服务端分层](layering.md)

## 规则

- 服务端位于 `{{SERVER_DIR}}/`，入口是 `<入口包>`，HTTP 框架使用 `<框架>`；迁移入口 `<迁移命令>`，运维脚本 `<运维命令>`。
- 目录按分层组织，依赖方向与装配规则见[服务端分层](layering.md)；新增目录前先确认现有结构无法承载。
- 需要与其它版本并存、便于对比验证的实现放在 `<版本实现目录>`，版本号与 `docs/versions/` 目录名一致；跨版本共享的代码不进版本目录。
- 依赖以依赖清单与锁文件为准，两者一并提交，构建时不解析浮动版本；新增依赖按[技术选型变更](../tech-change.md)执行。
- 配置通过环境变量注入，代码中不写死地址与凭证；本地默认值只用于本地，不进入发布产物。
- 本地开发默认连接本机 `<数据库>` 与 `<缓存>`；共享服务与访问边界见[服务端发布](../../delivery/server-deploy.md)。
- 部署形态（无状态、水平扩展、滚动更新、健康检查）见[服务端发布](../../delivery/server-deploy.md)；变更不得假设单实例。
- 本地启动使用 `<本地启动命令>`，由脚本补齐本地环境变量；不手写等效命令。
- 本地依赖端口与 e2e 环境保持一致；真机联调使用开发机局域网 IP，不能使用 `localhost` 或 `127.0.0.1`。
- 日志、指标与追踪按[可观测性](../../problems/observability.md)接入，不在业务代码里散落打印。

## 步骤

1. 确认入口、依赖清单与部署形态，新增依赖先说明用途与替代方案。
2. 用统一的本地启动命令拉起服务与依赖，检查 `/healthz`、`/readyz`。
3. 依赖或配置变化后同步依赖清单、锁文件、本地默认值脚本与部署配置。
4. 按[任务执行与交付](../../implementation/task-delivery.md)执行验证。

## 验证

- 服务与依赖可通过统一命令启动，健康检查通过。
- 依赖版本已锁定，无重复或冲突依赖。
- 本地依赖端口与 e2e 环境一致，真机联调使用开发机局域网 IP。
- 变更不引入单实例假设，可在多实例与滚动更新下运行。
- 配置缺失时启动失败并打印变量名，不使用兜底默认值。
