# Runbook：技术选型变更

## 适用场景

- 引入新依赖或技术、升级主版本，或移除不再使用的技术。

- [客户端运行](client/runtime.md)

## 选型原则

- 先确认现有依赖能否满足；能用标准库或已有依赖解决的不新增依赖。
- 同一职责只保留一种实现（一个 HTTP 框架、一个 ORM、一个测试框架）；新增前说明与现有实现的关系与迁移方式。
- 评估项：维护活跃度、许可证、已知安全问题、文档与社区、与现有栈的集成成本；停止维护或长期无更新的库不引入。
- 关键路径不引入 beta 或来源不明的依赖；必须引入时说明回退方案。
- 取舍维度只考虑架构合理性、可维护性、可扩展性与长期演进能力、部署上的平滑扩展能力，以及性能、资源占用、响应延迟和吞吐；可说明实施成本与风险，但不因工程难度、改造成本、历史包袱或兼容负担降低标准。

## 步骤

1. 说明用途、现有替代方案与影响范围，确认收益大于成本。
2. 在版本 `update/<需求>/technical.md` 记录变更与迁移方案，确认后再实施。
3. 更新依赖清单与锁文件，执行构建与静态检查。
4. 验证关键链路、性能与资源占用；升级时对比升级前后的指标。
5. 同步更新本 runbook 的项目选型表与相关文档。

## 验证

- 构建、静态检查与端到端测试通过。
- 依赖版本已锁定，无重复或冲突依赖。
- 选型表与仓库实际一致，移除的依赖无残留引用。
- 升级前后关键指标无明显退化。
