# Runbook：国际化设计

## 适用场景

- 设计或调整客户端、服务端技术方案，并预留国际化能力（文案外置、locale 透传、运营内容多语言、格式化与时区）。
- 方案当前只使用默认语言时同样适用：只确认预留入口存在，不实现翻译流程。
- 具体页面的文案内容与翻译质量见[UI 设计](../product/ui/ui-design.md)；本文只规定设计与数据结构层面的预留规则。

## 规则

### 通用

- locale 统一用 BCP 47 标识（`zh-Hans`、`en`、`ja`），客户端、服务端、数据与缓存使用同一套写法，不混用 `zh_CN` 这类下划线形式。
- 方案写明默认 locale、可支持 locale 与回退链；回退顺序为精确 locale → 同语言 → 默认 locale，任一级缺失时落到默认 locale。
- 用户可见文案与逻辑分离：代码、接口与数据结构中不保存面向用户的成品句子；文案按稳定 key 取值，key 发布后不复用、不改语义。
- 只有默认语言的阶段，四个预留入口必须存在：文案 key、locale 透传参数、数据中的 locale 维度、格式化入口；缺任一入口视为未预留。
- 文案 key 按页面或模块组织，不由中文原文生成；同一含义在客户端文案与运营内容中只对应一个 key。

### 服务端

- 系统固定文案不以成品文本返回：接口返回稳定错误码与结构化参数（数量、名称、阈值等），由客户端按 key 渲染。
- 运营内容（道具名、活动、公告、邮件、推送等）按 locale 存储与下发：内容表带 locale 维度或独立翻译表，主表只存稳定标识与可见性，读取按请求 locale 回退。
- 请求 locale 的来源与优先级在接口契约中写明，固定为显式字段或 `Accept-Language` 头加服务端默认值；不在各 handler 内自行解析语言。
- 时间统一 UTC 存储与传输；服务端只在业务日、活动周期等确需时区的计算中按用户时区处理，时区来源（用户设置或请求参数）写明。
- 金额以最小货币单位整数与币种传输，数字、日期、货币符号与千分位由客户端格式化，服务端不拼接展示串。
- 按语言排序、搜索与大小写折叠时指定 locale 与 collation，不用数据库默认排序代替；检索不假设单一语言的分词规则。
- 模板类下发（邮件、推送、短信）按 locale 选模板，模板与参数分离；日志、指标与告警文本不进用户文案体系。

### 客户端

- 用户可见文案全部来自文案资源，含按钮、错误提示、空态与无障碍标签；代码中不出现中文字面量，只有默认语言时也按 key 取值。
- 文案资源按 locale 分文件，键集合与默认语言一致；缺失 key 在构建或测试中失败，不在运行时显示 key 名或中文兜底。
- 文案支持占位符、复数与语序变化，不拼接句子，不按字符截取或长度判断布局。
- 布局不写死宽高与单行假设，允许文案膨胀 30%–40% 后换行；图标与图片中不含文字。
- 数字、日期、时间、百分比与货币使用平台本地化 API，按 locale 与用户时区格式化，不手写格式串。
- 语言切换写明生效范围（即时刷新、重进页面或重启应用）、选择持久化与首屏渲染前确定 locale，避免展示后闪切。
- 字体与排版写明 CJK 字形覆盖、RTL 镜像与行高字重差异；RTL 在布局约束阶段预留，不靠后期镜像补丁。
- 与服务端共享的枚举与错误码到文案的映射只在一处定义，页面不各自维护映射表。

### 数据与接口

- 运营内容的结构以「业务标识 + locale」定位一行，默认 locale 行必须存在；新增、更新与删除按 locale 行处理，不覆盖其他语言。
- 接口请求携带 locale（显式字段或 `Accept-Language`），响应内容与该 locale 对应；缓存键包含 locale，缺 locale 的缓存键视为缺陷。
- 错误响应只含错误码与结构化参数，不含成品文案；需要本地化的参数值（数量、名称）以结构化字段给出。
- 运营内容缺翻译时按回退链回落，回落到默认 locale 并记录缺失，不用空串或 key 作为展示内容。

## 步骤

1. 在 `technical.md` 的客户端与服务端方案中写出国际化维度：文案来源、locale 来源与优先级、运营内容的多语言存储与下发、格式化与时区归属、语言切换生效范围。
2. 列出本次新增或会展示的文案 key、运营内容字段与接口 locale 参数，标注落点文件。
3. 逐项核对预留入口：文案 key、locale 透传、数据 locale 维度、格式化入口、缓存键含 locale；只有默认语言时也逐项确认。
4. 与服务端确认错误码与结构化参数的返回形式，与客户端确认 key 到文案的映射位置。
5. 未确认事项写入版本 `open-questions.md`，不在方案中留待定分支。

## 验证

- 方案没有硬编码用户可见文案的计划，文案 key、locale 来源与回退链已写明。
- 运营内容的多语言存储形式与读取回退规则已写明，缓存键包含 locale。
- 接口不返回成品文案，错误响应为稳定错误码加结构化参数。
- 时间、金额、数字与日期的归属明确：服务端 UTC 存储与传输，客户端按 locale 与时区展示。
- 客户端方案写明文案资源组织、缺失 key 检测、文案膨胀与 RTL 预留、语言切换生效范围。
- 只有默认语言时，文案 key、locale 透传、locale 维度与格式化入口逐项确认存在。
- 未确认事项已进入 `open-questions.md`。
