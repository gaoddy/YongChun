# Runbook：客户端运行

## 适用场景

- 客户端本地运行、构建参数、联调地址与实机验证相关的修改或排查。

## 前置读取

- [客户端分层](layering.md)

## 规则

- 客户端位于 `{{CLIENT_DIR}}/`；UI 设计、实现、改版与评审按[UI 设计 runbook](../../product/ui/ui-design.md)执行。
- 接口地址与渠道标识通过构建参数 `<构建参数>` 注入；代码中不硬编码环境地址。
- 本地联调使用 `<本地地址>`，真机使用开发机局域网 IP，不能使用 `localhost` 或 `127.0.0.1`。
- 页面、状态与数据源的分层与依赖方向见[客户端分层](layering.md)；页面不发请求，不直接读写本地存储。
- 状态作用域、刷新与失效规则按客户端分层执行；跨页面共享的数据单独定义生命周期。
- 本地缓存与持久化数据在升级、回滚或切换环境后可能不兼容，验证前先清除；只有版本升级确实需要时才引入迁移逻辑。
- 实机验证优先使用稳定设备与非 debug 构建，不将不稳定的 debug 运行作为默认验证方式。
- 构建与本地启动入口见[Make 构建入口](../../implementation/make.md)，不手写等效命令。

## 步骤

1. 确认本次改动所需的构建参数与联调地址。
2. 通过统一构建入口生成目标产物，指向联调环境。
3. 清除旧缓存后，在稳定设备与非 debug 构建上验证关键页面与真实接口数据。
4. 按[补充测试与验证](../../implementation/testing.md)执行验证并清理临时文件。

## 验证

- 构建产物可由统一入口生成，参数指向正确环境。
- 真机联调使用开发机局域网 IP，接口数据真实可用。
- 实机验证使用稳定设备与非 debug 构建，旧缓存已清除。
- 状态管理作用域与刷新失效符合客户端分层约束。
