# Runbook：数据结构设计

## 适用场景

- 新增或调整代码中的领域模型、值对象、传输结构（DTO、请求、响应、消息）与枚举。
- 数据库表、索引、迁移与列类型的变更不在此列，见[数据模型变更](database/schema-change.md)。

## 前置读取

- [目录结构与命名](directory-structure.md)

## 规则

### 通用

- 同一业务概念在领域模型、传输结构、表与文档中使用同一名称，对应关系按[目录结构与命名](directory-structure.md)的业务对象登记维护，不另起同义名。
- 结构按职责独立定义：领域模型承载业务规则与不变量，传输结构承载接口契约，持久化结构承载表映射；三者不共用同一类型，也不跨层直接传递。
- 每个字段写明类型、单位与可选性；`null` 只表示「未知」或「不适用」，其余情况用空集合、默认值或必填字段表达。
- 标识单独建模：主键、业务单号与外键使用不同类型，不互相赋值，也不以字符串混用。
- 取值集合用枚举或封闭联合类型，字段不传裸字符串；未知取值在解析处显式拒绝，不静默落默认值。
- 金额用定点数并写明币种与精度，时间用带时区的类型并写明精度，时长写明单位；不用浮点数表示金额，不传未标明时区的时间。
- 集合字段默认空集合而非 `null`，对外结构不暴露内部可变集合。
- 新增字段必须可缺省（可选或带默认值）；删除、重命名与收窄类型的顺序按[数据模型变更](database/schema-change.md)的兼容规则执行。

### 服务端

- 领域模型不依赖框架、ORM 与序列化注解；需要落库时在 infrastructure 层转换，转换函数集中在映射文件中。
- 传输结构只含接口字段，不含业务方法与持久化注解；领域模型不直接作为接口出入参。
- 校验分两层：传输结构校验格式、必填与长度，领域对象在构造时校验不变量；绕过接口的调用同样被拦截。
- 列类型与领域字段类型不一致时，在映射层显式转换；领域模型不保存逗号分隔字符串、JSON 字符串这类列形态。

### 客户端

- 接口返回结构原样映射为数据源模型，字段与接口一致；页面展示字段不混入接口模型。
- 状态层使用独立的视图状态结构，页面只读；接口模型不直接作为可变状态。
- 可选字段在类型上标明，渲染前处理缺失与空值，不用非空断言绕过检查。
- 反序列化集中在数据源层，页面与状态层不手写 JSON 解析。

### 文档同步

- 每个领域模型、值对象、传输结构与枚举在 `docs/current/technical/<模块>/models/` 下对应一个文件，文件同步原始定义代码并列出字段的 `keypath`、类型、说明与产品的对应关系，形式见[文档结构](../docs/structure/docs-structure.md#数据结构文档)。
- 新增、修改或删除结构时同一任务内更新对应文件与 `models/README.md`；字段表缺少 `keypath`、类型或产品对应关系，或定义代码与源码不一致，视为未同步。

## 步骤

1. 从需求、页面与接口中列出名词与不变量，标注每个名词所属模块。
2. 区分领域对象、值对象与枚举，确定标识与相等性规则。
3. 为每个字段确定类型、单位、可选性与默认值，写明 `null` 的语义。
4. 分别定义领域模型、传输结构与持久化映射，跨层转换只放在映射处。
5. 按服务端与客户端分层放置结构，补不变量与序列化测试。
6. 在 `docs/current/technical/<模块>/models/` 更新结构文档：同步原始定义代码与 `keypath` 字段表，并同步接口文档中的字段定义。

## 验证

- 同一概念在领域模型、传输结构、表与文档中同名，无同义类型。
- 领域模型不依赖框架、ORM 与序列化注解；传输结构不含业务方法；持久化结构只出现在映射层。
- 每个字段有类型、单位与可选性，`null` 有明确语义。
- 不变量在构造或领域方法中校验，绕过接口写入同样被拒绝。
- 序列化与反序列化测试通过，新增字段对旧数据可缺省。
- 每个结构在 `docs/current/technical/` 有对应文件，定义代码与源码一致，字段表覆盖全部 `keypath` 并写明与产品的对应关系。
- 构建与静态检查通过：`<构建命令>`、`<静态检查命令>`。
