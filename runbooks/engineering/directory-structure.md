# Runbook：目录结构与命名

## 适用场景

- 新增或调整顶层目录、源码目录、模块归属与命名约定。
- 登记或调整业务对象与模块、表、接口前缀的对应关系。

## 前置读取

- [根规则的触发与必读](../../AGENTS.md#触发)
- [任务执行与交付](../implementation/task-delivery.md)
- [文档写作](../docs/docs-writing.md)（目录归属）

## 规则

### 顶层目录

- 顶层按职责划分：规则在根 `AGENTS.md`，运行手册由 runbook 仓库提供（位置见 `AGENTS.md` 声明），文档在 `docs/`，服务端在 `{{SERVER_DIR}}/`，客户端在 `{{CLIENT_DIR}}/`。
- 新增顶层目录前先确认现有目录无法承载；新增后同步更新根 `README.md` 的结构树与本文。
- 文档目录职责见[文档写作](../docs/docs-writing.md)与[文档回写](../docs/docs-sync.md)。

### 源码目录

- 源码目录按分层组织，分层细节见[服务端分层](server/layering.md)与[客户端分层](client/layering.md)。
- 生成物有固定输出位置，并随源契约一起提交。
- 迁移与运维脚本单独存放，不与业务代码混放。
- 测试、临时文件与构建缓存不放在源码目录内，也不随提交进入仓库。

### 命名

- 目录与文件统一小写，多词用 `-` 连接；同一项目内不混用命名风格。
- 名称表达业务概念，不使用 `util`、`common`、`manager`、`helper` 这类无边界名称；公共能力按能力命名。
- 接口路径用复数资源名（kebab-case），数据库表与字段用 snake_case，代码标识符遵循 `<语言规范>`。
- 同一概念在代码、接口、表与文档中使用同一名称，不出现同义词。

### 业务对象

- 每个核心业务对象登记所属模块、表与接口前缀；新增对象时补一行，迁移或重命名时同步更新。

## 步骤

1. 确认现有目录与模块能否承载改动，不得已才新增目录或模块。
2. 在版本 `update/<需求>/technical.md` 说明目录变化与模块职责。
3. 按命名约定调整目录、文件、接口与路由。
4. 同步业务对象登记。
5. 更新文档中的目录结构与命名。

## 验证

- 目录归属正确，新增目录已在本文或版本 `technical/` 登记。
- 命名在代码、接口、表与文档中一致，无无边界名称与同义词。
- 业务对象登记与仓库中的模块、表、接口前缀一致。
- 文档中的目录与命名和仓库一致。
