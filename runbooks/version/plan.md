# Runbook：任务计划

## 适用场景

- 任务开始前规划执行方式、实施中跟踪进度，或在合并前清理计划。
- 计划文件的结构与命名见[版本文档结构](../docs/structure/version-docs-structure.md#计划-plans)。

## 前置读取

- [版本文档结构](../docs/structure/version-docs-structure.md)

## 规则

- 阶段顺序固定：产品确认 → 技术确认 → 任务拆分；前一阶段未确认时不进入下一阶段，也不产出后续文件。
- 计划只管理任务执行；产品与技术结论放在 `update/`，计划中链接引用，不复制。
- 任务按可独立验证的粒度拆分；每个任务明确文件边界，多个任务不并发写同一文件。
- 实施阶段按任务派发子 agent 执行；子 agent 统一使用主 agent 的 worktree，派发与隔离规则见[Worktree 与分支](../implementation/worktree.md)。
- 并行任务之间没有依赖才可同时进行；有依赖的按顺序排列并在计划中写明。
- 范围变化时先改计划再改代码；实施中的偏离记录在计划里。
- 纯文档或规则任务在计划中注明无产品改动与技术实现。
- 计划随任务分支提交，完成任务后、合并前删除，不随分支合入主分支。

## 步骤

1. 确认任务所属版本、关联的需求目录与分支名。
2. 按[版本文档结构](../docs/structure/version-docs-structure.md#计划-plans)建立计划目录与文件，记录当前阶段。
3. 产品确认后更新阶段状态；技术确认后再写任务规划。
4. 拆分任务，写清每个任务的输入、产出、文件边界与验证方式。
5. 实施中更新任务状态与偏离说明；范围变化时先更新计划。
6. 合并前删除计划目录，确认未随分支合入主分支。

## 验证

- 阶段顺序正确，未确认阶段不产出后续文件。
- 每个任务可独立验证，文件边界清晰，并行任务无文件重叠。
- 计划未复制 `product.md`、`technical.md` 的内容，只保留链接。
- 合并后主分支无计划目录残留，worktree 已清理。
