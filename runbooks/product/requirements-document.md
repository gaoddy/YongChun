# Runbook：产品需求文档

## 适用场景

- 汇总或更新全部产品需求，维护需求总表与单个需求文档。
- 执行中出现需要用户定夺的事项，或需求实现版本、状态发生变化。
- 技术可行性调研见[产品功能可行性调研](feature-feasibility.md)；产品规则的完备性审查见[产品定义文档](product-definition.md)。

## 前置读取

- [产品定义文档](product-definition.md)
- [文档结构](../docs/structure/docs-structure.md)

## 文档落点

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| 需求总表 | `docs/requirements/README.md` | 全部产品需求一行一条，兼作目录索引 |
| 需求文档 | `docs/requirements/<slug>.md` | 一个需求一份，跨版本保留 |
| 版本技术方案 | `docs/versions/<版本>/update/<需求>/technical.md` | 按[需求变动](../version/requirement-change.md)维护 |
| 已实现状态 | `docs/current/product/` | 实现完成后回写 |

- slug 与版本 `update/<需求>/` 同一规则，建立后不改名。
- 需求文档长期保留，不随版本完成删除；已否决需求保留行与文档，不删除。

## 需求总表

表头固定，不增删列：

| 编号 | 需求 | 状态 | 实现版本 | 待定夺 | 需求文档 |
| --- | --- | --- | --- | --- | --- |
| `R001` | 一句话需求 | 已确认 | `0.0.1` | 无 | `docs/requirements/<slug>.md` |

- 编号从 `R001` 起按建立顺序递增，不复用；需求合并或否决后编号不回收。
- 状态取「待确认」「已确认」「实施中」「已实现」「已否决」之一，与实际进度一致。
- 实现版本写具体版本号或「待定」；未确定版本的需求照常登记，不因待定而不汇总。
- 待定夺写项数（如「2 项」），无则写「无」。
- 需求列写一句话需求主题，与需求文档标题一致；需求文档列写相对链接。

## 需求文档

固定章节，顺序不变：

| 章节 | 内容 |
| --- | --- |
| 状态与实现版本 | 状态、实现版本；未确定写「待定」 |
| 背景与目标 | 需求来源、要解决的问题、目标用户与使用场景 |
| 需求规则与验收 | 可验收的产品规则与验收标准，只写产品层 |
| 排除项 | 本次明确不做及原因 |
| 待定夺事项 | 编号、事项、影响、提出日期；无则写「无」 |
| 定夺记录 | 日期、事项、结论、确认人 |
| 关联文档 | 版本 `update/` 目录、`docs/current/product/` 文档、决策记录 |

- 待定夺事项表头为「编号、事项、影响、提出日期」，编号从 `Q001` 起递增。
- 定夺记录表头为「日期、事项、结论、确认人」，可注记对应的待定夺编号。
- 不写接口、表结构、实现方案与任务拆分。

## 主源与同步

- 需求文档是需求与产品规则的唯一主源；版本 `product/` 与 `update/<需求>/product.md` 只写相对需求文档的版本裁剪或调整，无变化不建。
- `update/<需求>/technical.md` 链接需求文档，不重复产品规则。
- 实现完成后按[文档回写](../docs/docs-sync.md)回写 `docs/current/product/`，需求文档状态改为「已实现」，同步需求总表。
- 需求相关的待定夺事项写入需求文档；版本 `open-questions.md` 只登记跨需求或归属不明的事项，同一事项不重复登记。
- 满足[决策记录](../version/decision-record.md)门槛的结论另写入 `docs/decisions/`，需求文档只链接。

## 登记与更新时机

| 时机 | 动作 |
| --- | --- |
| 产品初始化给出功能列表 | 按功能登记需求与文档，状态「待确认」，实现版本「待定」 |
| 功能需求澄清完成 | 写入已确认规则、验收与待定夺，状态改「已确认」 |
| 需求变动提出 | 在总表登记或更新原需求，确定实现版本 |
| 执行中新增或调整 | 当轮更新原需求文档与总表，不新建副本 |
| 需要用户定夺 | 当轮写入待定夺事项，总表更新项数 |
| 定夺完成 | 移入定夺记录写结论，同步规则、状态与总表 |
| 实施中 | 状态改「实施中」 |
| 实现完成 | 状态改「已实现」，回写 `docs/current/product/` |
| 需求否决 | 状态改「已否决」，写明原因，保留记录 |

- 同一需求只保留一行与一份文档；重复、替代或合并时在原处更新并写明关系。

## 步骤

1. 在需求总表检索需求：已有则更新原行与原文档，不新建副本。
2. 新需求按建立顺序分配编号，在总表新增一行，建立 `docs/requirements/<slug>.md`，按固定章节写入。
3. 需求确认后回填实现版本；版本未定写「待定」，确定或变更时同一任务更新总表与文档。
4. 执行中出现需要定夺的事项时，当轮写入待定夺事项，并更新总表项数。
5. 定夺后把事项移入定夺记录，写入结论与确认人，同步需求规则与状态。
6. 实施与实现完成时更新状态，按[文档回写](../docs/docs-sync.md)回写 `docs/current/product/`。
7. 校验总表与文档一一对应、实现版本无空值、链接有效。

## 验证

- 每个产品需求在总表有且仅有一行，并有且仅有一份需求文档，无孤儿文档与重复行。
- 每行实现版本为具体版本号或「待定」，无空值。
- 待定夺事项与定夺记录完整；已定夺事项已从待定夺移除，并在定夺记录中写明结论。
- 状态与实现情况一致；已实现需求在 `docs/current/product/` 有对应内容。
- 需求文档是产品规则唯一主源，`update/<需求>/product.md` 未复制规则。
- 需求相关待定夺未在版本 `open-questions.md` 重复登记。
- 需求文档不含接口、表结构与实现方案。
- 相对链接有效，slug 与建立时一致。
