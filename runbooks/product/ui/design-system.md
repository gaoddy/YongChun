# Runbook：设计系统与公共 UI

## 适用场景

- 新增或调整设计令牌、图标、通用组件、交互模式，或判断某段 UI 是否应进入共享设计层。

## 前置读取

- [UI 设计](ui-design.md)
- [组件设计](components.md)

## 规则

### 分层

- 设计系统分三层：原子（primitives）→ 语义（semantic）→ 组件与场景（metrics/scenario）；原子与语义合称基础定义，组件与场景即业务定义。
- 原子层只定义原始取值与固定刻度，不表达用途与场景。
- 语义层按 colors、typography、spacing、shape、elevation、motion 六个维度定义用途取值，只引用原子层。
- 组件与场景层定义组件度量（metrics）与业务场景取值（scenario），只引用语义层。
- 引用只能自上而下：业务定义只引用基础定义，语义只引用原子，不跨层引用，不把下层取值复制到上层。
- 业务调整只切换组件与场景层引用的语义定义，不修改语义与原子定义。
- 基础定义按刻度扩展，不因单个业务场景新增或改动；新增需有两个以上场景复用。
- 页面与组件只使用组件与场景层，不直接引用语义层与原子层；直接引用下层会使业务切换失效。

### 落地

- 公共部分必须沉淀到设计系统代码并实际落地：视觉令牌、图标、通用组件、交互模式及适用于多个场景的状态表现；设计稿或方案不能替代共享实现。
- 新增或调整公共内容时优先扩展共享入口，不同步复制到页面。
- 共享层只放可复用的呈现与交互，业务规则与数据编排留在业务层。
- 功能场景或交互目的相同的页面，优先复用已有公共 UI；只抽取确有复用价值的部分，不为抽象而抽象。
- 修改共享 token、组件或布局前检查全部消费者，按实际影响同步调整和验证，避免只修当前页面而使其他场景表现不一致。
- 共享内容变更在同一任务内同步设计系统文档与受影响的页面、组件文档。

## 步骤

1. 判断待做内容是否会被两个以上场景使用，确定是否进入共享层。
2. 判断待做内容属于原子、语义还是组件与场景层：每层只引用下一层，不跨层取值。
3. 检索现有令牌、图标与组件，确认可复用、需扩展还是新增。
4. 在共享入口实现，保持有限变体且不含业务规则。
5. 检查全部消费者，按影响同步调整。
6. 更新设计系统文档与相关页面、组件文档。
7. 用页面级场景验证组合效果。

## 验证

- 公共视觉与交互已进入共享设计系统，页面内无重复实现。
- 共享内容不含业务规则与数据请求，变体有限。
- 三层引用单向且无跨层引用：业务定义只引用基础定义，业务调整只切换引用，语义与原子定义未被改动。
- 语义层未直接写原子取值，组件与场景层未直接写语义取值。
- 页面与组件未直接引用语义层与原子层。
- 全部消费者已检查并同步调整。
- 设计系统文档与页面、组件文档已更新。
