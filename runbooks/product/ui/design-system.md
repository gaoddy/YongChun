# Runbook：设计系统与公共 UI

## 适用场景

- 新增或调整设计令牌、图标、通用组件、交互模式，或判断某段 UI 是否应进入共享设计层。

## 前置读取

- [UI 设计](ui-design.md)
- [组件设计](components.md)、[设计 tokens](tokens.md)、[图标](icons.md)、[交互与反馈](interaction.md)
- [客户端分层](../../engineering/client/layering.md)（共享设计层入口）

## 规则

- 公共部分必须沉淀到设计系统代码并实际落地：视觉令牌、图标、通用组件、交互模式及适用于多个场景的状态表现；设计稿或方案不能替代共享实现。
- 新增或调整公共内容时优先扩展共享入口，不同步复制到页面。
- 共享层只放可复用的呈现与交互，业务规则与数据编排留在业务层。
- 功能场景或交互目的相同的页面，优先复用已有公共 UI；只抽取确有复用价值的部分，不为抽象而抽象。
- 修改共享 token、组件或布局前检查全部消费者，按实际影响同步调整和验证，避免只修当前页面而使其他场景表现不一致。
- 共享内容变更在同一任务内同步设计系统文档与受影响的页面、组件文档。

## 步骤

1. 判断待做内容是否会被两个以上场景使用，确定是否进入共享层。
2. 检索现有令牌、图标与组件，确认可复用、需扩展还是新增。
3. 在共享入口实现，保持有限变体且不含业务规则。
4. 检查全部消费者，按影响同步调整。
5. 更新设计系统文档与相关页面、组件文档。
6. 用页面级场景验证组合效果。

## 验证

- 公共视觉与交互已进入共享设计系统，页面内无重复实现。
- 共享内容不含业务规则与数据请求，变体有限。
- 全部消费者已检查并同步调整。
- 设计系统文档与页面、组件文档已更新。
