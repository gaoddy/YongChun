# Runbook：设计 tokens

## 适用场景

- 新增、调整或使用颜色、字体、间距、圆角、阴影、层级等视觉令牌。

## 前置读取

- [UI 设计](ui-design.md)

## 规则

### 定义

- tokens 是视觉取值的唯一来源；页面与组件不硬编码颜色、字号、行高、间距、圆角、阴影与层级。
- 按[设计系统与公共 UI](design-system.md#分层)分基础定义与业务定义：基础定义承载取值与固定刻度，业务定义承载用途与场景。
- 业务定义按语义命名（如 `color-danger`、`space-md`），名称表达用途；基础定义按刻度命名，不出现业务语义。
- 业务定义只引用基础定义，不直接写取值；页面与组件只使用业务定义，不直接引用基础定义。
- 深浅色是同一业务定义的两套基础定义取值，不复制两套组件或两套布局。

### 使用与变更

- 新增 token 前先确认现有刻度能否表达；优先复用，避免近似值堆积。
- 基础定义按刻度扩展，不因单个业务场景新增或改动。
- 业务调整只切换业务定义引用的基础定义，不修改基础定义本身。
- 不用任意值覆盖 token；确需例外时说明原因并登记，避免长期存在。
- 修改 token 前检查全部消费者，按影响验证页面与组件，不只看当前页面。
- token 定义在共享设计层并登记用途与取值；设计稿标注业务定义名而不是色值。

## 步骤

1. 确认需要的视觉维度与现有 token 能否覆盖。
2. 判断属于基础定义还是业务定义：基础定义只按刻度取值，业务定义只引用基础定义。
3. 按语义命名新增或调整，业务定义给出所引用的基础定义与深浅色取值。
4. 替换硬编码取值，检查全部使用处。
5. 在设计系统文档登记用途与示例。
6. 检查深浅色与各页面表现。

## 验证

- 页面与组件无硬编码视觉取值。
- token 命名语义化，刻度有限且无近似重复。
- 业务定义只引用基础定义且无直接取值，页面与组件未直接引用基础定义。
- 深浅色取值齐全，布局不随主题变化。
- 变更已覆盖全部消费者并登记。
