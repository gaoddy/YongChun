# Runbook：设计 tokens

## 适用场景

- 新增、调整或使用颜色、字体、间距、圆角、阴影、层级等视觉令牌。

## 前置读取

- [UI 设计](ui-design.md)

## 规则

### 定义

- tokens 是视觉取值的唯一来源；页面与组件不硬编码颜色、字号、行高、间距、圆角、阴影与层级。
- 按[设计系统与公共 UI](design-system.md#分层)分三层：原子（primitives）→ 语义（semantic）→ 组件与场景（metrics/scenario）；原子与语义合称基础定义，组件与场景即业务定义。
- 原子层只承载原始取值与固定刻度（色板、字号、间距、圆角、阴影、时长），按刻度命名，不出现用途名。
- 语义层按 colors、typography、spacing、shape、elevation、motion 六个维度按用途命名（如 `color-danger`、`space-md`），只引用原子层。
- 组件与场景层定义组件度量与业务场景取值，只引用语义层。
- 引用只能自上而下：不跨层引用，不把下层取值复制到上层。
- 页面与组件只使用组件与场景层，不直接引用语义层与原子层。
- 深浅色是同一语义 token 的两套原子取值，不复制两套组件或两套布局。

### 使用与变更

- 新增 token 前先确认现有刻度能否表达；优先复用，避免近似值堆积。
- 原子与语义层按刻度扩展，不因单个业务场景新增或改动。
- 业务调整只切换组件与场景层引用的语义定义，不修改语义与原子定义。
- 不用任意值覆盖 token；确需例外时说明原因并登记，避免长期存在。
- 修改 token 前检查全部消费者，按影响验证页面与组件，不只看当前页面。
- token 定义在共享设计层并登记层次、用途与取值；设计稿标注组件与场景层名称而不是色值。

## 步骤

1. 确认需要的视觉维度与现有 token 能否覆盖。
2. 判断属于原子、语义还是组件与场景层：每层只引用下一层，不跨层取值。
3. 按层命名新增或调整，语义层引用原子刻度，组件与场景层引用语义定义与深浅色取值。
4. 替换硬编码取值，检查全部使用处。
5. 在设计系统文档登记用途与示例。
6. 检查深浅色与各页面表现。

## 验证

- 页面与组件无硬编码视觉取值。
- token 命名按层区分，刻度有限且无近似重复。
- 三层引用单向且无跨层引用，页面与组件未直接引用语义层与原子层。
- 深浅色取值齐全，布局不随主题变化。
- 变更已覆盖全部消费者并登记。
