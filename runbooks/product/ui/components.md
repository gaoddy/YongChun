# Runbook：组件设计

## 适用场景

- 新增或调整通用组件、业务组件，或判断某段 UI 是否应抽成组件。

## 规则

### 复用判定

- 两个以上场景出现相同结构与行为时才抽通用组件；只出现一次的场景结构留在页面。
- 同一交互目的只保留一个组件实现；能力不足时扩展或新增合适边界的组件，不复制改造。
- 通用组件只做呈现与交互，不含业务规则与数据请求；业务规则与数据编排留在页面或状态层。

### 接口与边界

- 组件输入输出显式：属性、事件、插槽或子内容；不通过全局状态隐式传值。
- 属性命名表达用途，默认值合理；变体（尺寸、状态、色调）使用有限枚举，不接受任意值。
- 组件不读取环境变量与路由参数，这些由页面传入。

### 扩展与变更

- 修改共享组件前检查全部消费者，按影响同步调整并验证。
- 新增变体优先扩展现有组件；确需新组件时说明与现有组件的关系与替代范围。
- 组件导出入口统一，页面不从内部路径引用。
- 在设计系统文档登记组件用途、变体、禁用场景与示例。

## 步骤

1. 列出需要覆盖的场景与交互状态，判断复用范围。
2. 对照现有组件，确认可复用、需扩展还是新增。
3. 定义属性、事件与变体，确认业务规则不在组件内。
4. 实现并检查全部消费者，同步设计系统文档。
5. 用页面级场景验证组合效果。

## 验证

- 复用判定有依据，无重复实现同一结构。
- 组件不含业务规则与数据请求，接口显式。
- 变体有限且命名清晰，无隐式全局依赖。
- 共享组件变更已覆盖全部消费者并登记文档。
