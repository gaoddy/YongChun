按上述 runbook 执行用户本次的服务端发布请求。

执行要求：
1. 先确认目标环境、版本号与产物来源；未指明环境时先问清，不默认生产。
2. 只发布已合入基线分支的提交，任务分支不直接部署。
3. 发布前核对必需配置与 Secret 已就绪、迁移能被仍在运行的旧实例兼容；任一不满足时停止并报告，不进入滚动更新。
4. 破坏性变更拆成两步发布：先兼容读，再切换写；回滚只回退代码，不回退已执行的迁移。
5. 新实例通过 `/readyz` 后才接流量，确认旧实例在优雅停机窗口内退出，再按可观测性看板观察错误率与延迟。
6. 记录版本、提交、变更内容、迁移项与回滚方式。

完成判定：目标环境实例全部就绪且镜像与版本一致，发布期间无请求失败，关键指标回到基线，发布记录已写入。
